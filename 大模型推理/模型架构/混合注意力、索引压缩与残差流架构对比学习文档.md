## 2. 历史状态压缩了，信息到底去了哪里

### 递推矩阵与历史条目是不同数据结构

线性递推层把前缀吸收到有限大小的矩阵。对固定层数、头数、状态精度与并发数，单请求当前状态的空间不随序列长度 n 增长；但检查点、卷积窗口和混合模型的全局层仍占空间。

逐位置 KV 像一列历史条目。MLA 可以让每条更短，稀疏 Attention 可以少读其中一些，CSA/HCA 可以把多个位置压成一个条目。这三种优化改变的分别是条目宽度、读取数量和历史粒度。

用整理者的粗略容量模型表示：

```text
请求状态 ≈ N_rec × M_rec
         + N_hist × n × bytes_per_entry
         + 压缩/索引/窗口/检查点等额外状态
```

其中参数仅用于表达组成关系，不是四种模型通用的精确显存公式。将历史条目压缩率设为固定 r 后，`O(n/r)` 仍随 n 线性增长；它不是递推状态的 `O(1)`。

**小例子：** 读取 32768 个 token，某历史路径按 4 个压成 1 个，得到约 8192 个条目；长度翻倍时条目数也约翻倍。递推矩阵仍可能保持原形状，但不能据此直接恢复任意旧前缀。

### 不按结构名字给质量排座次

保存原始位置的 KV，不意味着每次都会读取全部位置；读取全部压缩条目，也不意味着能还原逐 token 的原始信息。训练数据、选择器质量、层间补偿与评测任务都会影响质量。

因此原文的“信息表征最好”“某家信息不如某家”适合作为待验证假设，不能当成跨模型的已证实排序。

## 3. IndexPool、QSA 与 CSA：压缩发生在不同路径

### 两条数据路径必须分开画

```mermaid
flowchart TD
    X[历史隐藏状态] --> I[Indexer keys]
    X --> K[核心 Attention KV]
    I --> P[池化为块摘要]
    P --> S[Query 对摘要打分并选块]
    S --> E[展开为原位置集合]
    E --> R[读取选中位置的核心 KV]
    K --> R
    X --> C[另一类设计：先压缩核心 KV]
    C --> T[选择或遍历压缩条目]
    T --> O[直接在压缩条目上做 Attention]
```

**图意解读：** 左侧沿池化、选块、展开到原位置的路径概括 IndexPool/QSA；中间直接压缩核心 KV 的路径概括 CSA/HCA。不是某个模型把两条路径都同时接上，也省略了位置编码与尾部处理。

| 方法 | 被压缩的对象 | 选择后读什么 | 关键例外 |
| --- | --- | --- | --- |
| GLM IndexPool | 四个 indexer key 以加权池化形成摘要 | 被选位置的核心 KV | 不能把 indexer cache 缩小比例当作整个 KV cache 缩小比例 |
| Qwen QSA | r=4 的 indexer keys 平均池化 | 将选中 micro-block 展开到原 token 索引 | 完整块需满足因果条件；最后不足一块的可见 token 单独纳入 |
| DeepSeek CSA | 核心 KV 被压缩，索引器在压缩历史上选择 | 压缩后的 KV 条目 | Flash/Pro 的 Top-K 不同；还有局部滑窗分支 |
| DeepSeek HCA | 历史以更高比例压缩 | 全部可见的高压缩条目，无稀疏 Top-K | “Dense”指压缩空间上的全遍历，不是原 token 空间的全量历史 |

依据为 GLM 官方博客、Qwen §2.1.2、DeepSeek §2.3。GLM 的加权池化是官方描述；“可学习比平均池化一定更好”并无同条件消融支撑，本文不采用这个推论。

### CSA 与 HCA：遍历全部压缩条目，不代表工作量总比 Top-K 大

**2026-11-02 补充复核：** [《大模型加速优化：Attention架构演进》](https://mp.weixin.qq.com/s/fJglfOaTUreYXjcIOdLH3A)（程序员Owen，公众号“AI修炼技术派”，2026-10-30 08:30:00，Asia/Shanghai）用缓存形状对照六种架构。其 HCA 一节将“不做稀疏筛选”直接推到“计算量上升”，需要补上长度条件。以下只按该文引用的 V4-Flash-0731 [固定配置](https://huggingface.co/deepseek-ai/DeepSeek-V4-Flash-0731/blob/7872f01b1d1fe23eabc4c98b48bffcef5a386062/config.json)与[参考实现](https://huggingface.co/deepseek-ai/DeepSeek-V4-Flash-0731/blob/7872f01b1d1fe23eabc4c98b48bffcef5a386062/inference/model.py#L490)复核，不替换前面 V4 报告 v1 的整体模型基线，也不涉及 V4.1。

![补充文章的 CSA 缓存组成](../../images/attention-cost-model/02-csa-state.jpg)

**图意解读：** 绿色是最多 128 条局部窗口记录，黄色是沿历史按 4:1 压缩的 main KV，红色是另一条 128 维 indexer key 路径。Top-K 控制本次读取哪些压缩记录，不会把完整黄色、红色历史都缩成 512 条；图中也没有计入压缩器的滚动状态和量化 scale。原文完整算子图另把 indexer 缓存标为 512 维，与固定配置的 `index_head_dim=128` 不符；本图的 128 维才与配置对应。

![补充文章的 HCA 缓存组成](../../images/attention-cost-model/03-hca-state.jpg)

**图意解读：** HCA 保留局部窗口与按 128:1 压缩的全局记录，不用 indexer 从中选 Top-K；它遍历的是全部**可见压缩记录**，不是重新读全部原 token。图只表达逻辑元素形状，既不是总显存图，也不是实测性能图。

**整理者算例：** 固定单层、单请求、一个 Decode query，令 T 是包含当前 token 的可见长度；只数主 Attention 中被读取的逻辑条目，忽略 attention sink、tile padding 和设备复制。配置给出 W=128、CSA Top-K=512、压缩率分别为 4 和 128：

```text
CSA 条目数 ≈ min(T, 128) + min(512, floor(T / 4))
HCA 条目数 ≈ min(T, 128) + floor(T / 128)
```

窗口原位置与全局压缩条目是不同表示，因此这里按两路条目相加；不把“所覆盖的原 token 范围有重叠”误当成重复计数。压缩器的权重与尾部处理仍由模型定义，4:1 也不表示每条摘要只依赖互不重叠的 4 个 token。

| 可见长度 T | CSA 主 Attention 条目 | HCA 主 Attention 条目 |
| --- | ---: | ---: |
| 32768 | 640 | 384 |
| 65536 | 640 | 640 |
| 131072 | 640 | 1152 |

这能反驳“HCA 必然比 CSA 做更多主注意力计算”的无条件表述；约 64K 只是该配置下的**条目数量交点**。HCA 没有 CSA 的索引打分与 Top-K，两者压缩器开销也不同，所以它不是整层 FLOPs 或时延的盈亏平衡点。HCA 的压缩率固定时，单步遍历仍随 T 增长；完整 Prefill 则要按各 query 的因果可见条目累加。

补充文章第六节把 CSA 的选择数回写成 2048，也混用了 V3.2 DSA 与 V4-Flash CSA；这里采用固定配置的 512。容量与矩阵乘法的共同计数口径见 [KV 容量地图](<../KV缓存/KV Cache 容量优化技术地图学习文档.md>)；[图源清单](../../images/attention-cost-model/SOURCES.md)记录全部 17 图的取舍。

### QSA 的具体例子：为什么还要管尾巴

设当前可见前缀为 14 个 token，块大小为 4。前三个完整块包含 12 个 token，末尾还有 2 个。索引器对完整可见块打分，选中块展开为原位置；最后不完整块的可见 token 另行保留。

这避免把未来位置混入摘要，也说明 `512 blocks × 4 = 2048 tokens` 只是主要预算口径，实际访问还需要说明尾部规则。原文只说“固定平均池化”，不足以独立实现正确的 causal attention。

QSA 报告还说明先池化内容、再为块赋予位置编码，避免直接平均不同旋转相位。本文将它作为设计约束理解，未审计实际 kernel 的 masking。

### O(n²/r) 并不表示复杂度阶数变成线性

若 Prefill 中 n 个 query 都对约 n/r 个摘要打分，索引工作量可近似为 `O(n²/r)`。r 固定时仍是二次阶；单步 Decode 只有一个新 query，对历史摘要的打分约为 `O(n/r)`。这两个式子针对不同工作单位。

此外还要加上索引投影、Top-K、数据读取、核心 Attention 和其他模型层的成本。索引候选数缩小 4 倍不等于端到端速度提升 4 倍。

## 5. mHC、AttnRes、GR 怎样改变跨层信息流

### mHC：约束直接残差混合，而非保证整个模型不放大

教学表达为：

```text
X_next = B × X + C × F(A × X)
```

X 包含多个残差分支；A 读入子层，F 执行子层变换，C 写回，B 负责原残差分支之间的混合。mHC 将 B 约束为非负、每行和每列均为 1 的双随机矩阵，让这条直接残差映射具有受控的传播性质。

约束的是 B 这条路径，不是证明整个 F、优化器、量化和训练过程永远稳定。原文“解决数值不稳定”应理解为方法目标与论文证据，不是无条件保证。

### Single-Pass mHC：提前准备读入权重，消除一次残差重读

**人话版：** 原版需要先看完整份当前残差，才能决定怎样混合它。Single-Pass 改用前一个 block 已准备的读入权重，让正在生成的残差分块可以立即参与混合。这里的“前一个”沿网络深度计数，不是前一个生成 token。

![原版 mHC 的状态更新与系数生成](../../images/single-pass-mhc/01-original-mhc.png)

**图意解读：** 对一个 token，`X_l` 是 n 路、每路 d 维的残差，`A_l` 将其读入子层 F，`B_l` 混合残差分支，`C_l` 将子层输出写回。三个系数来自当前 `H(X_l)`；H 的归一化与投影需要跨隐藏维归约，因此当前 `A_l` 要等所有分块处理后才能得到。

![Single-Pass mHC 将输入混合改为使用前一 block 的系数](../../images/single-pass-mhc/02-shifted-input-mixing.png)

**图意解读：** 只把 F 的输入从 `A_l X_l` 改为 `A_(l-1) X_l`；`B_l`、`C_l` 仍由当前状态产生，H 也仍要计算，当前得到的 `A_l` 留给下一 block。两张图都是原文公式截图，窄屏可对照下面的文字流程；这项依赖改动不保证与原版逐值等价。

| 分块执行到哪里 | 原版 mHC | Single-Pass mHC |
| --- | --- | --- |
| 用上一 block 的输出更新一块 `X_l` | 可顺手累积 H 的投影和归一化统计 | 还可立即用已就绪的 `A_(l-1)` 混合这一块 |
| 全部隐藏维分块处理完 | 获得当前 A，需再次读取 X 才能混合 | 当前 A 供下一 block 使用，无须为本次输入混合重读 X |

报告把结构改动称为 Single-Pass mHC，把部署融合称为 Mega-mHC；后者把残差更新、输入混合、系数预测与输入 pre-norm、FP8 转换一起处理。预训练仍使用多 kernel 实现。不能仅看模型采用 Single-Pass，就认定任意引擎已经执行相同的融合路径。[报告 §2.4.1](https://arxiv.org/html/2609.19969v1#S2.SS4.SSS1)

**访存算例：** 下表沿用报告的局部计数模型，单位是相关激活的**读写元素总数**。为看清差别，取 `n=4`，保留 d 不变；它既不是全模型 FLOPs，也不是实测 HBM 字节数。

| 实现口径 | 元素读写量 | n=4 |
| --- | --- | --- |
| 原始多 kernel mHC，加输入 pre-norm | `(4n+4)d` | `20d` |
| 保留原版依赖，做两遍融合 | `(3n+2)d` | `14d` |
| Single-Pass 配合 Mega-mHC | `(2n+2)d` | `10d` |

整理者拆账：边界映射读取 n×d 的旧残差和 d 维上一子层输出，写出 n×d 的新残差与 d 维当前子层输入，因此是 `(n+1)d` 读加 `(n+1)d` 写。相对原始实现，`10/20=50%`；相对两遍融合，只再减少 `4/14≈28.6%`。这个下界限定于上述大激活映射，不包含模型权重、全部系数缓冲或 F 内部的数据流；不同精度的元素也不能统一乘同一个字节数。

**排障提示：** 先确认模型依赖、实际 kernel 路径及计数对象，再检查带宽和端到端耗时。少一次残差遍历不等于 KV 减半，也不推出请求延迟减半；本文没有质量消融或 GPU 测量结果。

### AttnRes：沿深度选表示，不是沿 token 做检索

普通残差把历史层输出逐步合入一条状态；AttnRes 用数据相关权重读取前序表示。Block AttnRes 进一步将一段层内的信息聚合为 block 表示，再跨 block 选择。

若 L 为层深、N 为 block 数、d 为表示宽度，报告中从 `O(Ld)` 到 `O(Nd)` 的比较针对这部分表示存储与通信开销，不能解释成整个模型 Attention 或 KV cache 的复杂度变化。

### GR：读取按通道门控，写回按分支控制

GR 保留四条残差分支。报告中的读入步骤对分支分别归一化，并生成分支×通道的门控，然后聚合为子层输入；子层输出写回时使用每分支标量权重。两端不是同一个门控粒度。

| 问题 | mHC | Block AttnRes | GR |
| --- | --- | --- | --- |
| 优化对象 | 多分支之间的受约束混合 | 前序 block 表示的选择性读取 | 加宽分支的门控读写 |
| 主要信息来源 | 当前多分支残差状态 | 前序 block 及当前局部聚合 | 当前多分支残差状态 |
| 系统代价应查什么 | 混合与归一化读写、约束计算 | block 表示保留、聚合及跨 PP 通信 | 分支归一化、门控与写回带宽 |
| 不应混淆 | B 的约束与整个网络稳定性 | 深度 Attention 与 token Attention | 逐元素读门与逐分支写门 |

本节是对报告机制的教学解释，没有得出三者的普遍质量/速度排序。

## 6. 从架构表走到推理系统，需要再补哪些条件

| 架构特征 | 系统问题 | 需要验证的证据 |
| --- | --- | --- |
| recurrent 与历史 KV 混合 | 同一前缀怎样恢复完整状态 | 各类缓存的合法共同边界、卷积和检查点 |
| 索引压缩后再读原 KV | 索引变便宜是否仍被 KV 读取限制 | indexer、Top-K、gather 与核心 Attention 分段耗时 |
| KV 历史真正压缩 | 位置与尾部如何更新、跨实例如何传 | 压缩块元数据、局部状态、布局与生命周期 |
| 宽残差或跨 block 聚合 | 算子少了是否仍消耗更多内存带宽 | 张量存活区间、重计算、PP 交接与 kernel trace |
| sparse/dense/linear 混合 | Prefill 与 Decode 是否受同一瓶颈限制 | 分阶段、分 batch、分上下文长度的实验 |

先固定模型变体、代码版本、精度、硬件与并行布局，再比较容量、延迟与质量。不同模型的“全局层少”“压缩率高”可以解释设计方向，不能替代同条件性能数据。

## 7. 自测与面试组织方式

可以按“历史状态 → 选择路径 → 深度路径 → 验证边界”回答，而不背四家标签：

1. 固定大小的矩阵是否意味着整个模型缓存为常数？不意味着，混合的历史层、并发状态与检查点还要计入。
2. IndexPool/QSA 和 CSA 最核心的差别是什么？前两者压缩选择时使用的摘要，CSA 的核心历史 KV 也被压缩；还应说明窗口与尾部例外。
3. HCA 的 Dense 是原 token 的全量检索吗？不是，是在高压缩历史上的遍历。
4. mHC、AttnRes 和 GR 是否可以按一个数字排名？需要同模型、预算与任务的消融；单凭结构无法排名。
5. 看到“3:1”“61 层”“Top-K=512”可以拼成配置吗？不可以，必须核对模型变体、首尾例外与资料版本。
6. Single-Pass 的“上一 block”与“访存减半”各指什么？前者沿网络深度移用 A，后者相对原始多 kernel 的局部激活读写口径；都不是上一 token、整个模型或端到端速度的结论。
