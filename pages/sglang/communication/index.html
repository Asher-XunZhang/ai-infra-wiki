从语义到传输：RDMA 在哪一层？
任务语义
消息 / 张量 / KV→接口与后端
socket / process group / KV backend→实际搬运路径
依配置与硬件选择

这些不是一一对应的三条专线。同机 / 跨机描述位置，点对点 / collective 描述参与方式，TCP / RDMA 描述传输路径；不能单凭 “KV” 或 “collective” 判断是否走 RDMA。

SGLang 的 Mooncake wrapper 将指针与长度注册给引擎，并传入 transport 配置；默认 RDMA 与 TCP 等路径由配置和底层实现决定。注册内存、分配请求页、远端写入、调度请求是不同职责。本课只核对 SGLang 接口，没有运行或验证 Mooncake 底层网络行为。核对 wrapper ↗

先预测，再操作

为什么 All-reduce 和 All-gather 不能替换？

前者合并同一结果的局部贡献，后者收齐不同分片。切换算子，观察输出是 [11,22] 还是 [1,2,10,20]；形状和元素含义都不同。

P 的 page 7 必须写到 D 的 page 7 吗？

不必。页号各属于本地池，由交接元数据给出对应关系。切换“打散目标页”，A/B/C 的逻辑顺序不变，但物理落点和连续传输段数改变。

两个 Success 通知一定代表两个源端完成吗？

不一定。源码按源端 rank 身份去重；同一个 rank 重复通知不能代替另一个 rank 完成。

元数据非零后，请求一定能继续吗？

还要参与 rank 就绪、可选缓存恢复，以及提交时的 room 一致性等检查。用“不匹配”场景观察请求被终止，无法进入可调度队列。
