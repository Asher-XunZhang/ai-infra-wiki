多模态输入：位置展开与 Encode／Prefill／Decode 交接

文本 token、媒体原件、预处理张量、编码特征和 LM KV 不是同一个对象。拆开 Encode 是为了让编码阶段可以独立组织资源与复用，但会增加传输、排队、身份和生命周期管理。

本例将一幅 2×2 图块的示意媒体编码成 4×4 特征，再与两个文本位置组成 6 个 LM 输入位置。图块数、特征维度和位置数都是教学形状，不对应某个下载模型。

媒体占位位置为什么不能按一个 token 计算

Processor 先解码与整理媒体，并根据模型规则确定特征及位置布局。一个 <image> 占位符可能展开成多个位置；图片大小、裁剪、视频帧或音频切分还可能改变数量。

LM 接收的输入需要让文本位置与相应特征对齐。本例 p1…p4 对应四行图像特征，p0/p5 为文本。位置标签不冒充真实 tokenizer ID，真实 shape 和占位规则回到模型 processor 核对。

E、P、D 各自产生什么

E/PD 只把编码拆开；E/P/D 还要单独交接 P 生成的 LM KV。E 中具体包含哪些投影由模型与接口契约决定，本例将其并入编码特征适配。

接收到特征不代表 LM Prefill 已完成，分配到 KV 目标也不代表可读。跨实例还需核对传输就绪、兼容布局、必要元数据与引用收尾；本地引用不画成网络脉冲。

角色本例输入本例输出
E：Encode媒体与预处理身份已适配 LM 输入维度的编码特征及元数据
P：Prefill文本位置与编码特征语言模型各层的 K/V，以及继续生成所需状态
D：Decode可消费的 LM KV 与当前 token后续计算、输出 ID 与更新的 KV

同一个占位符不保证同一份可复用状态

特征复用至少要核对媒体内容、预处理与编码模型身份。切换到 img-B 时，旧 img-A 的候选作废，即使文本占位符完全相同也不能沿用。LM 前缀缓存还要核对自己的模型、位置与状态键。

将特征读入成本调为 5 u，比较本例 3 u 编码假设：缓存命中仍可能增加等待。收益依赖载荷、路径和资源条件，不从“拆开”或“命中”这两个词直接推出。

先预测，再解释

E 返回了编码特征，D 能否立即据此续写？

还需要模型 Prefill 建立可消费的 LM KV，以及相应的状态与就绪条件。

替换图片但保留相同 <image> 文本，能否直接命中旧 KV？

不能据此决定；媒体和预处理身份、输入位置以及模型缓存键都要匹配。
