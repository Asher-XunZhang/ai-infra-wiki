缓存感知路由与 Agent 恢复：提示、驻留和状态所有权

用两个 Worker 比较前缀局部性与负载，再让路由提示过期或恢复状态缺失，确认谁能决定实际复用。

先修与跨章回看
原理：请求路由与取消原理：KV Cache 与前缀复用引擎对照：生命周期与执行（独立版本）
Router 记录与 Worker KV 为什么会分离选点、转发、匹配与搬运分别看KV 保留只覆盖恢复材料的一部分固定源码

Worker 内的前缀缓存决定本实例能少算什么；Router 根据提示与负载选择实例；Agent 还要保存消息、工具结果和外部引用。这三层状态分别有自己的所有者和失效方式。

本例请求有 12 个输入位置，W0 的路由提示为 8，W1 为 0。排队时长直接给定为教学 u，并用差大于 4 的教学规则选点；它不是网关实际 load 的单位或生产阈值。剩余输入按每 4 个位置 1 u 推演，未测真实等待与计算。

本例把前缀提示抽象成教学位置数量，便于对照实际缺口；固定网关路径使用字符比例等信息，不能把它直接当作 Worker 的 token KV 数量。

Router 记录与 Worker KV 为什么会分离

固定源码的网关 cache-aware 路径维护路由历史树；其字符前缀、tenant 与 worker URL 不是 Worker 内的 token KV 页。历史更新也不等于一次请求已成功生成并保留了 KV。

Worker 驱逐、重启、失败请求和输入归一化差异都可能让提示过期。切换“已驱逐”后，选点提示仍为 8，实际可复用为 0，目标 Worker 必须重新检查。

选点、转发、匹配与搬运分别看

缓存亲和可能减少 Prefill，但热点 Worker 的排队又可能抵消这项收益。先平衡还是先看前缀，取决于策略与有效配置。固定源码的失衡分支还同时检查绝对差和相对门槛，不能把本例单阈值作为实际实现。

选中另一个 Worker 并不自动搬迁旧 KV。本图只传请求；目标 Worker 要么命中自己的状态，要么通过明确支持的恢复路径加载，或从更短前缀重算。传输与恢复的完成条件必须另有证据。

KV 保留只覆盖恢复材料的一部分

恢复前核对最终 token 输入、模型与 tokenizer revision、adapter、媒体和命名空间；还要知道各状态组能恢复到哪个共同边界，必要载荷是否已可读，以及本轮引用由谁持有。

Agent 的消息、工具结果、文件或任务引用并不包含在一份 KV 中。若工具结果缺失，缓存命中也不能替应用补出正确上下文。本例将这种情况保留为恢复材料未齐。

缓存 miss 时，完整上下文仍可支持重新 Prefill；能重建模型上下文又不等于应直接重做外部工具操作。会话保留、客户端重试和有副作用任务的执行身份由应用契约处理。

先预测，再解释

Router 提示命中 8 个位置，Worker 是否必须接受这 8 个位置？

不必须。Worker 仍要核对身份、驻留、各状态组与可读条件。

Agent 有完整消息与工具结果但 KV 丢失，是否一定无法恢复？

不一定。可以按支持路径恢复更短状态或重新 Prefill，代价与时延需另测。
