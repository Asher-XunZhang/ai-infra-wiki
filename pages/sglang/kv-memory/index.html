一个位置怎样找到每层的 KV？
R1 的逻辑 p8→请求映射：槽 12→第 ℓ 层 K[12] / V[12]

逻辑位置连续，物理页号不必连续。同一个槽号在不同层对应不同数值；请求映射不是 K/V 的第二份存储。

GPU、Host 与外部存储如何衔接？
外部存储 L3→Host L2→GPU L1

这是启用分层缓存后的回载方向，不属于上方普通 RadixCache 演示。找到外部副本，不等于 GPU 已有可供 Attention 读取的 KV；回载仍要分配设备位置并满足完成事件与调度门槛。

先预测，再操作

6 个位置扩到 8 个，还需要新页吗？

本例不需要。最后一页已有 2 个位置，再写 2 个刚好填满；但这些尾页空位仍属于 R1，不能当成可分给其他请求的空闲整页。

连续 6 个 token 相同，为什么只复用 4 个？

本例 page_size=4，普通 RadixCache 保留完整匹配页。剩余两个相同 token 所在页不完整，需要计算；这与同一请求继续使用自己持有的尾页是两件事。

R1 结束后，共享页可以马上回收吗？

R2 仍持有时不能驱逐。两条请求都结束后，页可以继续留在缓存；直到驱逐，才归还分配器。

空闲页变多，为什么设备显存占用未必下降？

静态 KV 池已经预分配 buffer。请求结束或驱逐归还的是池内位置，不是把整块设备内存交还系统；也不保证把旧字节清零。
