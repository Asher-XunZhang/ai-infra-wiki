P / D 在 Transformer 里做什么

切换计算阶段，观察相同模型层、不同输入形状与注意力范围。

普通自回归文本生成教学示意 · 非运行 trace源码 279339f113

P 和 D 都走完整的模型层。P 处理一段新位置，D 通常每条请求处理一个新位置。

不要把 P/D 对应成 Encoder / Decoder

这里以 Llama 风格的 decoder-only Transformer 为例。它的一层包含自注意力（Self-Attention）、前馈网络（MLP），以及归一化和残差连接；这样的层重复很多次。Prefill 与 Decode 都经过这些部分，再由输出头和采样步骤选出新 token。

区别在“这一次送进来多少新位置、能读取哪些历史 KV”，而不在“走模型的哪半边”。如果使用 PP，模型层会分到多个 stage，但一次 P 或 D 前向仍需走过整条流水线。

交互 · 一个位置的 Query 怎样读取 K/V

批量计算不等于看见未来

Prefill 可以在一轮前向中处理多个输入位置，因果遮罩仍规定位置 p2 只能看 p1、p2。Decode 的 y1 已有全部 prompt 作为历史，因此能读这些位置的 KV，也会为自身计算并写入 KV。

“P 常更偏计算、D 常更偏访存”是理解负载的出发点，不是硬件定律。批量大小、上下文长度、模型结构和 kernel 都可能改变瓶颈。

自测 · Decode 是否跳过 MLP，只从 KV 中取答案？

不会。KV 复用历史 attention 的 K/V；当前新位置仍要经过 attention、MLP 等完整模型计算，才得到下一 token 的分数。
