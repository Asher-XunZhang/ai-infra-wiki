一条请求怎样变成回答

单步走过 Prefill 与 Decode，看首 token 和 KV 如何出现。

普通自回归文本生成教学示意 · 非运行 trace源码 279339f113

Prefill 读入上下文并给出第一个输出；Decode 把刚生成的 token 送回模型，一步步接着写。

先认清三样东西

Token 是模型处理的编号单位，不一定是一个汉字或一个词；logits 是模型给候选 token 的分数；KV Cache 保存已经处理过的位置在各层 attention 中的键和值。把它理解为“下一轮可用的历史记忆”即可。

下面用 p1…p4 表示输入，用 y1、y2 表示输出；它们是位置标签，不是实际分词结果或模型预测。模型压缩为 3 层，逐层展示同一次 Prefill，再看一轮 Decode；后续重复用循环概括。

动画 · Prefill 怎样读完输入并产生首字

“算出来”与“看见了”是两个时刻

模型前向和采样发生在后端；输出还要经过结果处理、反分词、流式响应和网络。第一个 token 已采样，并不表示客户端已经收到。PD 分离还可能带来额外的交接等待。

停止也不等于立即抹掉所有 KV。请求自己的资源需要收尾；如果启用前缀缓存，符合条件的 KV 可以由缓存系统保留，以便未来复用。

自测 · 为什么有 5 个输出时，缓存里只出现 y1…y4？

y5 刚被采样出来，还没有作为输入经过下一轮前向。不要把“已输出 token 数”直接当成“已写入 KV 的输出位置数”。
