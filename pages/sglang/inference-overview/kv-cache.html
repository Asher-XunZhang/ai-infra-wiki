KV：模型留给下一轮的记忆

拖动前缀命中与生成轮数，区分复用、新算与尚未写入。

普通自回归文本生成教学示意 · 非运行 trace源码 279339f113

KV 缓存省去历史位置的重复计算；它不是已经写好的答案，也不是模型权重。

同一个 token，在每层都有一份状态

每层根据自己的输入计算 K/V，后续 token 在这一层读取这一层的历史 KV。hidden states 是本轮逐层传递的中间结果，权重是模型参数，KV 则随上下文增长，三者的内容与生命周期都不同。

前缀复用要求 token 前缀匹配且状态兼容、可用；不是语义相似就能命中。下图假定请求有 8 个输入位置，匹配的前缀已经在可用的设备缓存中。

交互 · 相同 token，不同层的独立 K/V

为什么长上下文让 Decode 也变重？

虽然普通 Decode 每轮只有一个新位置，它仍需在每一层使用历史 KV。对稠密 attention 而言，历史越长，访问的数据通常越多。“每轮输入一个 token”不等于“每轮工作量与上下文无关”。

请求结束后可以释放请求占有的资源，也可以把可复用前缀交由缓存管理器保留。缓存保留不意味着这条请求还在 Decode；未来复用也可能需要回载或重新准入。

自测 · 两个 prompt 意思一样，就能直接共用 KV 吗？

不能这样推断。这里讨论的是匹配的 token 前缀和兼容的模型状态；措辞变化或前缀不同可能改变各层计算结果。
