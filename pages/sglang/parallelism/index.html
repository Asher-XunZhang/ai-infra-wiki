为什么 Attention 的 DP 不等同于独立服务副本？

不同层的计算和权重组织不同，一种布局未必同时适合 Attention 与 MoE。层内按请求分组，和在服务入口复制整个模型，是不同层级的设计。

展开机制与具体例子

在本页 TP=2、Attention DP=2 的 dense 层路径中，两组 Attention 各处理自己的请求。LayerCommunicator 在 MLP 前收集激活行，MLP TP 完成后再取回本组结果；请求队列与 KV 不参加该次 gather。

取舍与条件：更适合某层的分组可能引入布局转换与通信；是否能与其他并行选项组合，必须核对当前固定版本的约束。

读图后，应该能判断这些问题

收到 PP 请求对象后，下一级就能执行模型吗？

还需要对应 microbatch 的 proxy。请求对象用于维护调度状态；hidden_states 与 residual 才是继续模型层的输入。本级 KV 不在所选 proxy 载荷中。

为什么 Attention DP 的 Gather 不会把两份 KV 池合在一起？

LayerCommunicator 整理的是本轮 hidden_states 行。MLP 需要同一行序才能让各权重分片产生可正确规约的结果；请求历史 KV 仍由各 Attention 组维护。

SP 的 entry_scatter 和 Row Reduce-scatter 是同一种操作吗？

entry_scatter 对已经复制在各 rank 的输入作本地切片；Row 的 Reduce-scatter 要合并多个 rank 的计算贡献，并把求和后的序列片分到各 rank。两个名字都带 scatter，数据条件不同。

为什么 DCP 不能只把局部 Attention 输出取平均？

每块 KV 的 softmax 分母不同。必须携带 LSE，以匹配的指数底校正贡献；本页独立算例得到 0.2×2+0.8×6=5.2，而简单平均为 4。

Collective 算法、通信 backend 与完成条件继续看模块 07 · 通信与传输；PD 的 KV 交接继续看分离部署。
