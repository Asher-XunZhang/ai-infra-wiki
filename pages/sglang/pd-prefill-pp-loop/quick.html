为什么图里要同时标 L、M 和 s？

Loop 是控制循环的一次推进，microbatch 是经过模型层的工作，slot 是临时保存相应状态的位置。它们的编号用途不同，不能凭数字相等推断对象相同。

记住这四件事，就能读这张图

  1. loop 是调度线程的一轮工作。一个 L# 外框对应一次本地 for mb_id 迭代，里面可能准备 M3、处理旧 M1，并清理更早的请求。相同 L# 在不同 PP rank 上不同时发生。
  2. 提交 forward 不等于 GPU 已算完。大方块画 CPU 调度区间；高亮 batch 后，下沿进度带显示它的 GPU 前向及计算前后经历的等待。进度带跨过方块边界，就表示本级线程已经进入后续 loop，而该 batch 仍在计算、传输或等待。
  3. 有些事属于共享队列。bootstrap 检查、L2 ACK、控制共识可能处理多个请求或历史状态，不能统一归到当前 M#。M1–M5 在本例共同准入，进入 waiting queue 后再依次选批。
  4. 算完还没结束。旧结果回流、本地结果处理、KV 发送和释放各有条件；收到 output 不等于 Decode 已收全 KV，传输结束后也可能继续等待释放共识。
为什么把很多小步骤合并成这五组？

按源码中的连续顺序合并：A → 检查状态；B+C → 缓存与选批；D+E → 提交前向；F+G+H → 结果与共识；I → 转发保存。空槽不会凭空多出 forward，缺失的分组会标为“本轮跳过”。

bootstrap 的本地轮询在前、共识回流和准入在后；若强行合成一个连续时间段，会掩盖它跨轮推进的事实。因此它在第一组检查状态，在第四组推进共识。L2 ACK 检查与当前 batch 的缓存准备则合到第二组，但说明中仍区分共享队列与当前 batch。

同一张图中的 batch 进度带按生命周期区间组织，包含排队和等待，不表示持续占用 CPU/GPU。大步骤高亮依据原模型明确记录的对象和实际 release 名单；M1–M5 共同接收/准入的操作用虚线。未明确标出请求成员的通用 bootstrap / 终态轮询不会被擅自归给某个 M#，它们仍在 loop 中显示。

请求变慢：等待发生在计时器内，还是外？

预测：客户端多等 120 ms 和 Scheduler 多等 120 ms，会让基准工具的 TTFT 同样增加吗？

操作：打开 请求秒表，依次选择“基准请求”“客户端许可多等 120 ms”“Scheduler 多等 120 ms”。比较首包位置与 TTFT 起点；再选“Prefill 耗时减半”，检查它能消去哪段等待。

核对结果与证据边界

本例客户端多等许可让总等待增加，适配器内 TTFT 不变；Scheduler 排队增加则计入 TTFT。缩短 Prefill 无法消除其余等待。许可包装 在 适配器计时起点 之外。数值是教学设定；线上验证需采集同一请求的客户端许可、发送、调度与首包时刻。

定位入口：01 系统边界 → 02 请求运行时 → 06 调度 / 04 执行；11 服务治理 检查是否真正可服务，12 性能分析 核对计时口径。

请求结束：共享 KV 为什么仍不能回收？

预测：R1 与 R2 共用前缀页；R1 结束后，分配器能否立即把该页分给 R3？

操作：打开 KV 与内存 的“共享回收”，逐步走到 R1 结束、尝试驱逐、R2 结束和再次驱逐。盯住共享页的引用连线与归属，区分请求槽位、缓存占用与底层 buffer。

核对结果与证据边界

R1 结束后 R2 仍保护共享页；R2 结束让它可驱逐，真正驱逐后才归还 allocator。解除保护 与 驱逐归还 是两个动作；预分配设备 buffer 不随每次请求结束销毁。线上验证要观察引用、受保护/可驱逐量和 allocator 容量，不能仅看进程显存。

关联 05 KV 与内存 和 06 调度准入；再用 10 模型与生成 比较 recurrent checkpoint，说明为什么不能把普通 KV 页的规则直接套到所有状态上。

PP 的 GPU 都算完了：为什么请求还没清理？

预测：仅延长 PD KV 传输，会同时推迟最后一段 GPU 前向和所有请求清理吗？

操作：在本页比较“原示例”与“PD KV 传输偏慢”，跟踪同一份 batch 的计算终点、KV 在途和释放。接着在 通信课程 的“就绪与回收”选择“元数据晚于 KV”和“元数据 room 不匹配”，分别判断 D 的下一步。

核对结果与证据边界

本例固定选批与充足资源，KV 变慢拉长清理尾部，GPU 完成点不变；真实容量压力可能反过来影响后续准入，不能外推不变。PP 终态交集 同时包含成功和失败；P 清理与 D 就绪 仍是两条条件链。线上验证需分别记录各 rank 的 sender poll、release 共识与 D 侧 gate，不能用一个等待指标当原始网络拷贝时间。
