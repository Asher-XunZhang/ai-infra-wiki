HiCache 完整回载：从 L3 命中到当前层可读

找到缓存以后，为什么还不能立刻计算？

KV Cache（键值缓存）保存注意力计算中的历史 K/V。前缀索引回答“哪里有可复用副本”，Attention 实际读取的是当前 GPU 上已经就绪的内容。HiCache 把更多副本放到主机和可选存储中；要让下一条请求使用它，还需分配目的地址、搬运、等待对应层可读，并处理传输引用。

本课采用固定源码的 UnifiedRadixCache、Python TreeCore、FULL-only、cache 主机模式，单 rank、单 GPU、非投机。L1/L2/L3 分别指设备池、主机缓存池和可选存储后端，不是 CPU 硬件缓存层级。

跟踪 R1：存在、读入、可用、收尾

同一段前缀在三层中保持身份。先看 L3 查询命中，再看 L2 读入与采用、L1 分配与复制。用观察点暂停，分清“本层可读”和“整批传输收尾”。

L1/L2/L3 是存储层，0/1/2 是模型层。R1 使用同一段前缀 S；H2D 是主机→GPU 的复制，ACK 是完成记录。

沿同一段 KV，看五道门槛

① L3 命中：先知道“存在”

exists 返回连续前缀的存在范围；此时还没有读入 KV。前缀长度要满足预取阈值，还要取得 L2 目标空间，才会提交 get。

② L2 读入：先落到目标，再采用

后台把 KV 写进主机目标。读完不等于已由缓存侧采用；结果交接后，缓存管理侧才能把合法前缀插入主机树。本例选择整段读完再采用，并在同一段收尾消费 L3 最终 ACK；真实路径可以交接部分连续进度。

③ L1 回载：索引先返回，复制后完成

load_back 先保护主机源和已有设备路径，再尝试分配 L1。成功时把传输入队并返回设备索引；start_loading 才启动本批逐层 H2D。索引、已分配目标与可读内容是不同状态。

④ 逐层可读：本层复制完成即可读取

每层的 GPU 完成事件（event）连接本层 H2D 与 Forward stream。Forward 只等自己要读的那一层；后面的层可以继续复制。这个等待是 GPU stream 的依赖，不是要求 CPU 一直阻塞。

⑤ H2D ACK 收尾：解除本次传输保护

最后一层复制完成后，后续调度轮次才能消费带完成事件的 H2D ACK。loading_check 解除本次主机源与设备路径的传输引用；请求自己的设备前缀引用另算。

两类 ACK 的对象不同。L3 的结果/最终 ACK 处理主机读入与所有权交接；H2D ACK 处理主机到设备的整批回载。两者都不能代替逐层 event，也不自动代表请求完成或所有 KV 已释放。图中不把 ACK 画成 KV 数据传输脉冲。

三种持有关系，分别在什么时候解除？

持有者保护什么本例中的结束条件
L3 后台 IO仍可能写入的 L2 目标有效结果采用时交接对应部分；取消分支等待最终 ACK 交还剩余所有权。
本次 H2D 回载主机源与已有设备路径；成功分配后的 L1 目标失败则撤销临时保护；成功则待复制完成且 CPU 消费 H2D ACK 后解除本次传输引用。
R1 请求正在使用的 L1 设备前缀沿请求生命周期解除。本图停在前缀恢复和回载收尾，不结束 R1，因此末帧仍可持有。

取消不等于立即归还。切换到“L3 IO 中取消”：本例尚无已采用前缀，R1 取消后不再采用本次结果；但后台仍可能写目标。最终 ACK 消费后，剩余所有权交回并进入释放队列；释放队列实际调用主机池 free 后，目标才归还。它们在图里是两个独立阶段；分开呈现只为辨认先后条件，不表示固定的排队等待或后端终止时延。

这一步只归还本次未采用的新 L2 目标；其他请求的缓存、R1 原设备前缀沿各自生命周期处理，本图不展开。真实路径还要分别处理部分已交接前缀、辅助 pool 和释放队列，不能将任意取消概括成一次 free。

解除保护也不等于删除数据。正常回载后，L2 副本仍可留作可回收缓存；L1 前缀仍由 R1 的请求引用保护。是否驱逐副本要看缓存策略与其他持有者，不能仅凭传输引用下降决定。

逐层可读，和整批收尾分别服务于谁？

本教学排程中，第 0 层 H2D 在 12 u 完成，Forward 随即读取；第 1、2 层复制仍可继续。三层到 18 u 才全部完成，H2D ACK 在 19–20 u 被 CPU 消费。12 u、18 u 与 20 u 分别代表本层可读、整批复制完成和传输收尾，不是同一事件。GPU event 放入 stream 后，只有前面的拷贝实际完成，等待它的 Forward 才能继续；CPU 已提交 event 不代表数据已可读。CPU 消费整批 H2D ACK 用于解除传输保护，不能代替模型当前层的读取依赖。图里的复制与计算使用同一教学时钟，重叠只是这组依赖允许的一种排程，不给出实测收益。

存在前一轮 forward fence 时，H2D 还要先等旧执行对复用页的访问结束。这个“旧 forward→新 H2D”方向，与“新 H2D→当前层读取”方向相反。为聚焦本次恢复，主图假定旧 fence 已满足；不能据此省略真实实现的旧访问保护。

命中后回载失败，怎样继续？

设备分配失败或其他回载条件不满足时，init_load_back 可返回空的新索引，保留原设备 anchor。后续按实际剩余输入重新调度；主机命中长度不能提前算成已经省掉的 Prefill。

L3 查询成功也不保证 get 全部成功。真实读取可能只采用连续完成前缀；混合组件还可能要求完整状态。主图的“完整命中”不覆盖 SWA/Mamba、Rust TreeCore、所有布局和外部存储的数据面。

先预测，再解释

设备地址已经返回，本层是否一定可以读取？

还要等对应 H2D 层 event。索引、已分配空间和有效内容是不同条件。

第 0 层读完，是否可以立即解除全部传输保护？

不能。后续层与整批搬运仍可能在途，完成处理还要消费相应 ACK。

H2D ACK 收尾以后，Host 副本为什么仍在？

解除本次传输引用不会自动删除可复用主机副本；它还受缓存策略与其他持有者控制。

取消后，L3 最终 ACK 已消费，目标是否已经能重新分配？

还要看释放队列是否已经实际归还到主机池。ACK 交回所有权与 pool.free 是两个步骤；本例用独立阶段展示。

L2 读完、已采用，为什么 L1 仍显示不可读？

主机和 GPU 是不同的存储位置。还要取得 L1 目标并完成对应层 H2D；主机有效副本不能替代设备侧完成事件。
