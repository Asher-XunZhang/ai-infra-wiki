Speculative Decoding：草稿候选怎样验证和接受？

在普通逐 token 生成之上，增加候选、验证和回退。

可单步操作原理与实现分开来源与教学边界

先看：自回归生成：Prefill 与 Decode 怎样接续？ · KV Cache 与前缀复用：为什么保存历史 K/V？

目标模型一次拿到一串草稿。先看它为什么能并行验证，再观察第一处分歧怎样决定哪些输出和 KV 可以留下。

调用对照操作演示机制画布为什么这样做选读与取舍术语速查来源

先提出候选，再验证前缀

同一串草稿候选，第一次分歧在哪里？

全部通过：接受整个草稿前缀；中途分歧：保留分歧之前的候选；首个分歧：没有草稿候选被接受

亮色为已接受前缀；分歧后候选不再提交。全部通过时再补出一个 token；补出的 token 需下一轮输入后才有自己的有效 KV。

目标模型每次检查几个位置？

普通自回归：目标模型逐个生成；推测解码：草稿提出，目标集中检查

草稿生成与目标验证都要做工作；一次检查多个位置不等于一次普通单 token 调用的成本。

草稿与验证速览：同一最终提交序列，调用组合不同

三种条件使用同一组草稿候选和同一条贪心验证规则。下表把“普通目标逐 token 调用”与“4 次草稿 + 1 次目标验证”并排；两种方式最终提交的序列相同，但目标调用、草稿调用和验证调用的成本并不相等，表中次数不是速度比。

有效 KV 只含根 token 与接受的连续前缀；替代或补出的 token 尚未作为输入，不计入。1 次验证覆盖 5 个输入位置，不是 5 次单 token 调用；普通目标调用与草稿/验证调用的成本不相等，不能把次数差折算成速度比。

为什么这样做？

未来未知，为什么验证时又能一起算？怎样在减少调用时保持目标模型的输出规则？为什么接受率高也不等于一定快？
01

未来未知，为什么验证时又能一起算？

草稿提供的是已知候选输入。目标模型可将候选放进同一次因果计算，得到各位置在草稿前缀条件下的结果。提交时从左到右确认；第一个不一致之后，各列的假设前缀已经变了，需要基于修正后的前缀继续。

例如前两个一致而第三个分歧，第三个用目标模型结果替换。第四列仍是以原来的草稿第三项为条件算出的，即使字符碰巧相同，也不能用那一列证明它在修正后的前缀下成立。

02

怎样在减少调用时保持目标模型的输出规则？

图里比较的是贪心解码：目标模型选中的下一项与草稿相同才接受。带随机采样时，目标是维持同一前缀下目标模型的输出分布。

随机采样怎样校正草稿？

标准投机采样先从草稿分布 q 抽候选 x。目标分布 p 和 q 都基于同一个已确认的前缀，且这个候选由 q 抽出，所以 q(x) 大于零。若目标给 x 的概率低于草稿，只按两者概率的比值接受它；否则总是接受。

从提出到接受，x 留下的概率质量是 p(x) 与 q(x) 的较小值。发生拒绝时，从目标分布仍短缺的部分按比例抽取。补上这部分质量，才使最终输出符合目标分布。

α⁡(x)=min⁡(1,p⁡(x)q⁡(x))r⁡(x)=max⁡(0,p⁡(x)−q⁡(x))p′⁡(x)=r⁡(x)∑vr⁡(v)

03

为什么接受率高也不等于一定快？

要把省下的目标模型调用与草稿、批量验证和整理有效状态的时间一起算。相同的接受长度下，更贵的草稿或更长的验证仍可能让总时间变长。

本课的调用对照只数目标模型被调用的次数。要比较服务表现，还要在相同负载和输出条件下量实际时间；图里的接受项数不能直接当作加速倍数。

试着解释

为什么正式输出的最后一项，可能还没有自己的 KV？

展开解释

验证计算只给作为输入的位置写 KV。最后由目标模型补出的 token 刚被选中，下一轮送回模型时才作为输入。上轮已输出的根 token 则在本轮进入计算并获得 KV。

第 3 个草稿被拒绝，第 4 个碰巧与另一结果相同，就能越过第 3 个保留吗？

选读与取舍

Accepted Prefix：为什么只能连续接受候选

把分歧从第 3 项移到第 1 项，观察同一草稿的可提交前缀怎样缩短。首处不一致后的验证列使用了错误的前缀。

Root / Bonus Token：正式输出与有效 KV 的偏移

验证输入包含上一轮已输出的根 token。新补出的 token 尚未作为输入计算，因此输出列表和有效 KV 列表即使长度相同，成员也不一定一样。本例正式输出为“我、想、吃”，若继续跟踪 KV，它对应“根、我、想”；主图先看接受和输出，第三章再展开 KV 提交与 EAGLE 的实现边界。

Acceptance Rate 与开销：何时可能获得收益

调用次数只说明目标模型被唤起几次。真实代价要把草稿与验证均计入，并固定解码策略和到达负载。

术语速查
草稿
尚未确认的候选序列；可以来自小模型或其他提议方法。
验证与提交
验证检查候选是否符合目标规则；提交后才成为有效输出及相关状态。
回退
撤销未被接受的部分，保留有效前缀；不是把用户已看到的任意文字偷偷删掉。
