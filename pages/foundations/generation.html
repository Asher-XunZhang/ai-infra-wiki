自回归生成：Prefill 与 Decode 怎样接续？

第一轮选出的 token 怎样进入下一轮？把 Prefill、Decode、输出选择和客户端可见的时刻接起来。

可单步操作原理与实现分开来源与教学边界

先看：Transformer 前向总览：从输入向量到下一 token · Attention 与 Q/K/V：模型怎样参考上下文？

输入、续写与可见输出

同一个模型，两次调用处理哪些位置？

Prefill：先处理输入，再选首个输出；Decode：读历史，计算一个新位置

Prefill 处理一段输入；Decode 处理新位置并读取历史 KV。刚选出的输出在下一轮进入模型后才有自己的 KV。

模型为什么要一轮一轮地生成？

自回归环：每轮选出的内容影响后续预测

选出的 token ID 成为下一轮输入；客户端看到的文字还要经过反分词和传输。

面对同一组候选，两种选择怎样不同？

贪心：选概率最大的候选；抽样：按概率分布选择候选

教学分布：A 60%、B 30%、C 10%。贪心取最大值；固定抽样点 0.75 落在 B 的概率区间。

生成一个 token，就一定发一条消息吗？

逐个发送：一个消息包含一个 token；合并发送：一个消息包含多个 token

网络消息可以合并多个 token；消息到达间隔与逐 token 生成间隔需要分开观察。

01

为什么一次预测一个 token，也能形成一段话？

设 x 是已经给定的输入，y₁、y₂ 是要生成的前两个 token。第一个只以 x 为条件。第二个以 x 和已经选出的 y₁ 为条件。选出「学习」后，下一步就在「我想学习」之后预测；换成「吃」，第二步就要使用另一组分数。

训练时完整样本已知。模型用位置 i 及其可见前文预测 i 后面的 token，把真实的下一项作为监督目标。因果遮罩挡住目标及更远位置，因此训练可以同时算多行预测。推理需要先选出这些未来输入，才知道接下来算哪条路径。

P⁡(y1,y2∣x)=P⁡(y1∣x)·P⁡(y2∣x,y1)

依据：自回归生成与解码策略 · Hugging Face · Vaswani 等（2017）· Attention Is All You Need

02

Prefill 为什么能处理多位置，Decode 为什么逐轮推进？

Prefill（预填充）处理已知 prompt，并留下各层的历史 K/V。最后一个输入位置的 logits 用来选出第一个生成 token。此时它只是刚选出的 ID，还没有自己的 K/V。

下一次 Decode 才把这个 ID 作为输入。新位置读旧 K/V、生成自己的 K/V，再给下一个 token 打分。不同请求仍可以同批执行，依赖链是对每一条普通自回归请求分别成立的。

03

分数、概率、采样分别有什么用？

Logits 是原始分数。贪心选择最大 logit，采样把分数转换成概率后按分布抽取。动画中的分支固定了抽样结果，真实采样还可能经过温度缩放或候选过滤。放宽分布会让低分候选更有机会出现。

选出的 ID 经过反分词后才能发给客户端。一个响应片段可能含多个 token，甚至要等后续字节才能显示完整文字。遇到结束标记、长度上限或取消时，调度器按各自条件结束生成并收尾。

按累计概率选一次 token

按候选表的顺序累加概率。贪心取分数最高的候选。采样先从 0 到 1 均匀抽取一个数 u，再选择累计概率首次达到 u 的候选。

图里的「学习」「休息」「。」分别占 60%、30%、10%。若抽到 0.75，就落在「休息」的区间。切换到下一轮时，已经选出的词会进入上下文，模型要重新算分数和概率。

cnext=argmaxcscFc=∑b≤cpbcnext=min⁡({c∣Fc≥u})

试着解释

为什么已知 prompt 可以多位置计算，未知回答却通常逐步选择？

展开解释

Prompt 的所有输入位置已确定，可以在因果遮罩下组织计算。回答的下一位置取决于本轮选了什么；选择变化，后续条件也变化。

刚采样出的第一个输出，是否已经作为输入算过自己的 K/V？

选读与取舍

Model 与 Inference Engine：模型和引擎的分工

模型根据输入和已有状态做计算，产生候选分数；推理引擎组织请求、安排计算、管理缓存并把结果返回。SGLang 是第三章要拆解的引擎之一，不是这些 token 的词表，也不是模型权重本身。

Autoregressive Generation：输出为何成为下一轮输入

跟踪被送回输入区的同一个 ID。已有历史留在缓存里，只有新位置输入这次 Decode；已选出但尚未送回的下一项仍在生成边界外。

Detokenization：输出 ID 怎样成为可见文字

若一个 token 只携带尚不完整的字节，反分词和响应端可能等字节凑齐再显示。因而选择次数、消息条数和客户端看到的更新次数可能不同。

模型权重
训练得到、推理时用于计算的一组参数；普通生成不会每输出一个字就训练一遍。
logits / 采样

先分清五个操作

温度 T>0 时将分数除以 T，再做 softmax。T 较小时分数差更明显；较大时分布通常更平。T=0 在所选路径进入贪心处理，不执行除以零。

top-k 限定排序后的候选个数；top-p 按概率质量限定前缀集合。二者结合时，最终可选集合受到两项约束，剩余权重还要归一化。

重复惩罚使用本例已生成历史 “学习”两次、“。”一次；本例 r=2 时，正分 2 变 1，负分 −1 变 −2。它不同于按次数线性减分的 frequency penalty，也不等于把整个 prompt 做一遍词频统计。

用同一组数字走完整个转换

默认 z=[ln25,ln9,ln4,0]。T=2 后指数权重为 [5,3,2,1]，概率为 [5/11,3/11,2/11,1/11]。top-k=3 去掉最后一项，top-p=0.6 再去掉第三项，保留质量为 8/11。

归一化后 q=[5/8,3/8,0,0]；固定 u=0.75 落在第二项区间。固定 u 让两个条件可以复查，不是一次真实随机采样或模型复现性实验。不同条件下 q 改变，同一个 u 的落点也可能改变。

常见 top-p 概念图保留累计达到门槛的最小前缀。本实验核对固定 SGLang PyTorch 代表路径，其删除条件是“该候选之前的累计概率 > top_p”；等号保留。动画值避开默认等号边界，源码注解保留这项差异。同分在本例按 ID 排序，实际后端的同分与随机实现另核对。

选择概率、返回概率与停止原因分别看

过滤前 p 与过滤后 q 通常不同。展示 top_logprobs 的数量只决定返回多少列，不等于采样的 top-k。不能拿一个概率字段就推断实际可选集合。

先预测，再解释

增大温度是否一定得到更长、更正确的回答？

不能。温度改变本轮分布；输出长度还由后续候选与停止条件决定，质量需要独立验证。

top-k=1 时，原始 softmax 概率一定为 1 吗？

只有过滤后的选择分布成为单候选。原始或截断前概率仍可能小于 1。
