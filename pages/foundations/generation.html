自回归生成：Prefill 与 Decode 怎样接续？

先处理输入，再给下一片段打分；把选出的片段接回去，才能继续下一轮。

可单步操作原理与实现分开来源与教学边界

先看：Tokenization 与 Embedding：文字怎样变成模型输入？

输入准备好了，模型也不会一次交出整篇回答。一次选择一个 token、再把它送回继续生成，这叫自回归。下面先看一组明确标为教学假设的候选怎样从分数变成概率并完成一次选择；再用“自回归完整过程”回看两次续写，或进入“Detokenization 与流式可见”观察同一个输出 ID 怎样经过反分词和传输到达客户端。

先想清楚：这一课解决什么问题？

语言模型学到的是：给定已有内容，下一个单位有哪些可能。自回归生成把这个局部问题反复求解；Prefill 和 Decode 则是推理系统执行这条依赖链时的两种工作形态。

01

为什么一次预测一个 token，也能形成一段话？

一段序列的概率可以分解为一连串条件概率：先预测第一个输出，再在它和原输入的条件下预测第二个，依次继续。模型每步给词表里的候选打分，解码规则再选择一个 token。选中的结果会改变后续条件，所以不能预先独立选出整段回答。

训练时可以拿到完整样本，把每个位置后面的真实 token 作为目标；因果遮罩保证预测时看不到目标之后的内容。推理时未来输出尚未选定，只能沿已经作出的选择推进。

同一问题可以走向不同的后续

  1. 已有输入：“我想”。第一步若选“学习”，下一步是在“我想学习”之后预测。
  2. 若第一步选“吃”，后续就要根据“我想吃”重算，不能沿用前一路径的候选分数。

这是依赖关系示意，未运行模型，也没有声称这些候选的真实概率。

依据：自回归生成与解码策略 · Hugging Face · Vaswani 等（2017）· Attention Is All You Need

02

Prefill 为什么能处理多位置，Decode 为什么逐轮推进？

Prompt（输入提示文本）里的 token 都已经确定，Prefill（预填充）可以一次组织这些位置的计算，并建立后续需要的缓存；各位置仍只能读取因果遮罩允许的内容。最后一个输入位置的输出用于选择第一个生成 token。

随后把刚选出的 token 作为新输入，就进入 Decode（解码）的下一轮。新 token 经过模型各层，更新缓存并产生下一个候选。单条普通自回归请求每轮推进一个新位置，多条请求仍可放在同一批中计算。

03

分数、概率、采样分别有什么用？

Logits 是模型对候选的原始分数。Softmax 将它们转为总和为 1 的概率；贪心解码选最高分项，随机采样则依据经过温度、候选过滤等规则处理后的分布抽取。温度调节分布的尖锐程度，不是事实正确率的旋钮。

直到选择结束标记、达到长度限制或被取消，生成才停止。概率是在当前上下文和模型下对续写的偏好，不代表回答已经过事实核验。

依据：自回归生成与解码策略 · Hugging Face

试着解释

为什么已知 prompt 可以多位置计算，未知回答却通常逐步选择？

展开解释

Prompt 的所有输入位置已确定，可以在因果遮罩下组织计算。回答的下一位置取决于本轮选了什么；选择变化，后续条件也变化。

术语速查

模型权重
训练得到、推理时用于计算的一组参数；普通生成不会每输出一个字就训练一遍。
logits / 采样
logits 是候选的原始分数。选择策略可以取最高分，也可以根据分布抽样；分数不是事实正确率。
Prefill / Decode
先处理一段输入并获得首个输出，称为 Prefill；随后用新位置与历史状态继续生成，称为 Decode。

Model 与 Inference Engine：模型和引擎的分工

模型根据输入和已有状态做计算，产生候选分数；推理引擎组织请求、安排计算、管理缓存并把结果返回。SGLang 是第二章要拆解的引擎之一，不是这些 token 的词表，也不是模型权重本身。

逐层观察：同一次前向怎样经过三个模型层

Prefill 读入上下文并给出第一个输出；Decode 把刚生成的 token 送回模型，一步步接着写。

先认清三样东西

Token 是模型处理的编号单位，不一定是一个汉字或一个词；logits 是模型给候选 token 的分数；KV Cache 保存已经处理过的位置在各层 attention 中的键和值。把它理解为“下一轮可用的历史记忆”即可。

下面用 p1…p4 表示输入，用 y1、y2 表示输出；它们是位置标签，不是实际分词结果或模型预测。模型压缩为 3 层，逐层展示同一次 Prefill，再看一轮 Decode；后续重复用循环概括。

“算出来”与“看见了”是两个时刻

模型前向和采样发生在后端；输出还要经过结果处理、反分词、流式响应和网络。第一个 token 已采样，并不表示客户端已经收到。PD 分离还可能带来额外的交接等待。

停止也不等于立即抹掉所有 KV。请求自己的资源需要收尾；如果启用前缀缓存，符合条件的 KV 可以由缓存系统保留，以便未来复用。

自测 · 为什么有 5 个输出时，缓存里只出现 y1…y4？

y5 刚被采样出来，还没有作为输入经过下一轮前向。不要把“已输出 token 数”直接当成“已写入 KV 的输出位置数”。
