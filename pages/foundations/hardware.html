GPU 计算与访存：算力、带宽和 CUDA Graph

先算一个小矩阵，再区分参数存储、数据搬运、设备运算和执行提交。

可单步操作原理与实现分开来源与教学边界

先看：Attention 与 Q/K/V：模型怎样参考上下文？ · Batch 调度：动态组批、连续批处理与 Chunked Prefill

模型权重是一组数，GPU 要拿到这些数和输入，才能执行乘加。我们用一个两行矩阵把运算展开，再用相同工作量比较带宽和算力变化。

先想清楚：这一课解决什么问题？

神经网络计算既要做乘加，也要把权重和激活送到运算单元。算力、数据搬运和 CPU 提交都可能成为限制；先找受限制的环节，才能判断应该优化什么。

01

为什么很多模型运算适合 GPU？

一个矩阵乘法包含许多结构相近的乘加，GPU 能同时安排大量这类工作。权重是训练好的参数，激活是当前输入在计算过程中产生的中间数值；两者到达计算位置后，运算才能进行。

小任务、数据准备、同步或频繁提交可能让设备无法持续处理足够工作。因此“在 GPU 上跑”不等于“算力已经充分使用”。

02

算力很强，为什么仍可能在等数据？

Arithmetic Intensity（算术强度）描述每搬运一定字节的数据，执行了多少运算。复用已经读取的权重、合适地组织批量，可能让同一份数据参与更多计算；仅增加计算单元，无法缩短必须的数据读取下界。

把数据复用和执行速度分开看

  1. 假设一份权重 W 读取一次后可供 4 个输入使用，它每次读取承担的计算量多于只服务 1 个输入。
  2. 实际还需读取激活、写出结果，且缓存和算子实现决定能否达到这种复用。

这是复用关系示意，没有将请求数直接换算为加速倍数。

依据：GPU 计算与带宽 · NVIDIA

03

CUDA Graph 解决的是另一种什么等待？

CPU 需要把设备操作提交给 GPU。对重复出现且满足约束的执行结构，CUDA Graph 可以预先组织操作图，再重放它，减少反复逐项提交的开销。

重放仍会执行本次输入对应的运算；它不是缓存上一次答案。形状、地址和执行结构的要求由具体实现决定，图桶补齐也可能多做一些工作。

试着解释

如果数据搬运已经占主导，只把算力翻倍会怎样？

展开解释

计算部分可能缩短，但搬运数据的下界并未改变。应先确认瓶颈，再考虑复用数据、减少搬运或改进带宽。

术语速查

权重与激活
权重是模型参数；激活是本轮计算产生的中间结果。读取权重不是读取已经写好的回答。
算子 / kernel
算子描述要做的运算，kernel 是设备上执行它的一种实现；一个 kernel 通常不等于整个模型。
算力 / 带宽
前者约束单位时间能做多少计算，后者约束能搬多少数据；两种资源不能互相替代。

对照算例，回看机制与取舍

矩阵乘加：一行输出怎样算出来

输入 [2,3] 与权重两行 [1,2]、[3,4] 计算，得到 [8,18]。图逐行展开 2×1+3×2 与 2×3+3×4。真实模型的维度更大，原理上的乘加关系相同。

Compute-bound / Memory-bound：算力与访存瓶颈

后半段用教学工作量给出搬运 8 u、计算 3 u 的两个资源下界。即使算力翻倍，搬运的下界仍是 8 u。这里的 max 是理想下界，不保证实际能完全重叠；真实延迟还含调度、提交、同步等成本。

CUDA Graph：减少哪些执行提交开销

程序需要把一组设备操作提交出去。CUDA Graph 可以捕获并重放满足条件的操作图，以减少相关提交开销；它不会把模型计算凭空删除。第二章会用真实请求和补齐行区分图桶容量与请求数量。
