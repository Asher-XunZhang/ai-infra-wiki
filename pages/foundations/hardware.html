GPU 计算与访存：算力、带宽和 CUDA Graph

先算一个小矩阵，再区分参数存储、数据搬运、设备运算和执行提交。

可单步操作原理与实现分开来源与教学边界

先看：Attention 与 Q/K/V：模型怎样参考上下文？ · Batch 调度：动态组批、连续批处理与 Chunked Prefill

模型权重是一组数，GPU 要拿到这些数和输入，才能执行乘加。我们用一个两行矩阵把运算展开，再用相同工作量比较带宽和算力变化。

先想清楚：这一课解决什么问题？

神经网络计算既要做乘加，也要把权重和激活送到运算单元。算力、数据搬运和 CPU 提交都可能成为限制；先找受限制的环节，才能判断应该优化什么。

01

为什么很多模型运算适合 GPU？

一个矩阵乘法包含许多结构相近的乘加，GPU 能同时安排大量这类工作。权重是训练好的参数，激活是当前输入在计算过程中产生的中间数值；两者到达计算位置后，运算才能进行。

小任务、数据准备、同步或频繁提交可能让设备无法持续处理足够工作。因此“在 GPU 上跑”不等于“算力已经充分使用”。

依据：GPU 计算与带宽 · NVIDIA

02

算力很强，为什么仍可能在等数据？

Arithmetic Intensity（算术强度）描述每搬运一定字节的数据，执行了多少运算。复用已经读取的权重、合适地组织批量，可能让同一份数据参与更多计算；仅增加计算单元，无法缩短必须的数据读取下界。

把数据复用和执行速度分开看

  1. 假设一份权重 W 读取一次后可供 4 个输入使用，它每次读取承担的计算量多于只服务 1 个输入。
  2. 实际还需读取激活、写出结果，且缓存和算子实现决定能否达到这种复用。

这是复用关系示意，没有将请求数直接换算为加速倍数。

依据：GPU 计算与带宽 · NVIDIA

03

CUDA Graph 解决的是另一种什么等待？

CPU 需要把设备操作提交给 GPU。如果每个 kernel 很短，GPU 算完上一个时，CPU 可能还没准备好下一个，时间线上就出现空档。CUDA Graph 将满足条件的操作及依赖先组织成可执行图，重复运行时用一次图提交减少这类开销。

普通异步提交也允许 CPU 在 GPU 计算时准备后续操作。若计算足够长，后续提交可以被覆盖，减少 CPU 工作不一定明显缩短总耗时。真实系统还可能存在 GPU 侧的提交与调度成本；本课时间线先聚焦 CPU 提交造成的等待。

捕获记录工作而不执行被捕获的 GPU 运算，实例化后才可重放；这些准备需要成本。重放仍对本轮输入重新计算，且须满足实现的形状、地址及执行结构要求。第二章再展开图桶和补齐行。

试着解释

如果数据搬运已经占主导，只把算力翻倍会怎样？

展开解释

计算部分可能缩短，但搬运数据的下界并未改变。应先确认瓶颈，再考虑复用数据、减少搬运或改进带宽。

术语速查

权重与激活
权重是模型参数；激活是本轮计算产生的中间结果。读取权重不是读取已经写好的回答。
算子 / kernel
算子描述要做的运算，kernel 是设备上执行它的一种实现；一个 kernel 通常不等于整个模型。
算力 / 带宽
前者约束单位时间能做多少计算，后者约束能搬多少数据；两种资源不能互相替代。

对照算例，回看机制与取舍

矩阵乘加：一行输出怎样算出来

输入 [2,3] 与权重两行 [1,2]、[3,4] 计算，得到 [8,18]。两行分别计算 2×1+3×2 与 2×3+3×4。真实模型的维度更大，原理上的乘加关系相同。

Compute-bound / Memory-bound：算力与访存瓶颈

同一任务要搬 8 份等量数据、做 6 份等量计算。若带宽为每秒 1 份数据，搬运至少用 8 秒；若算力为每秒 2 份计算，计算至少用 3 秒。动画把格子按每秒容量重新分组，展示工作量 ÷ 速率 = 时间。算力翻倍后计算项为 1.5 秒，数据搬运仍至少 8 秒；带宽翻倍则把搬运项降为 4 秒。这是一个 Memory-bound（受带宽限制）的教学例子；计算项更长时才是 Compute-bound（受算力限制）。整体耗时至少达到两项中较大者，是否接近下界还取决于重叠、依赖与额外成本。

CUDA Graph：减少哪些执行提交开销

先看同一组 A → B → C：普通方式由 CPU 逐项提交；CUDA Graph 先记录操作和依赖、实例化成可重放的图，之后每轮提交整张图。上下时间线保持每个 kernel 的计算时长相同，让读者看到短 kernel 场景减少的是等待提交的空档。切换较长 kernel 后，普通方式也能提前提交后续工作，两条 GPU 时间线同时结束。两种情况都保留 CPU 与 GPU 的重叠，且图重放仍按新输入重新计算。首次准备有成本，需要通过重复执行摊薄。

8 份数据每秒搬 1 份，6 份计算每秒做 2 份。只把算力翻倍，整体的资源时间下界是多少？

自测与解释：8 份数据每秒搬 1 份，6 份计算每秒做 2 份。只把算力翻倍，整体的资源时间下界是多少？

计算下界变成 6÷4=1.5 秒，但搬运仍至少需要 8÷1=8 秒。因此整体至少 8 秒。
