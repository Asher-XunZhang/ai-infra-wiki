01

为什么很多模型运算适合 GPU？

权重是训练参数，激活由当前输入产生。把输入 [2, 3] 竖着写成一列，矩阵第一行与它逐项相乘并求和，得到第一项 8。第二行照样得到 18。输入列可被多行复用，各输出项也可以分别计算。

GPU 适合同时安排许多这种乘加。数据还没读到、工作太少或频繁同步时，算力可能用不满。一次算子得到的是中间结果，后续还要继续计算。

02

算力很强，为什么仍可能在等数据？

算术强度把运算量和搬运量放在同一口径下看。同一份权重读入一次后若服务更多输入，每个搬运字节能支持的运算量可能增加。核算时仍须计入输入激活、输出与中间数据，并说清统计的是哪层存储的流量。

动画里搬运要 8 个教学时间单位，计算要 3 个。即使两项能完全重叠，较长的一项也要做完，所以总时间的下界为 8。只把算力翻倍后，计算降到 1.5，下界仍是 8。如果两项必须串行或还有等待，实际时间会更长。

算术强度=浮点运算量搬运字节数搬运时间下界=字节数带宽计算时间下界=运算量算力T总≥max⁡(T搬运,T计算)

03

CUDA Graph 解决的是另一种什么等待？

CPU 需要把设备操作提交给 GPU。如果每个 kernel 很短，GPU 算完上一个时，CPU 可能还没准备好下一个，时间线上就出现空档。CUDA Graph 将满足条件的操作及依赖先组织成可执行图，重复运行时用一次图提交减少这类开销。

普通异步提交也允许 CPU 在 GPU 计算时准备后续操作。若计算足够长，后续提交可以被覆盖，减少 CPU 工作不一定明显缩短总耗时。真实系统还可能存在 GPU 侧的提交与调度成本；本课时间线先聚焦 CPU 提交造成的等待。

捕获记录工作而不执行被捕获的 GPU 运算，实例化后才可重放；这些准备需要成本。重放仍对本轮输入重新计算，且须满足实现的形状、地址及执行结构要求。第三章再展开图桶和补齐行。

试着解释

如果数据搬运已经占主导，只把算力翻倍会怎样？

展开解释

计算部分可能缩短，但搬运数据的下界并未改变。应先确认瓶颈，再考虑复用数据、减少搬运或改进带宽。

8 份数据每秒搬 1 份，6 份计算每秒做 2 份。只把算力翻倍，整体的资源时间下界是多少？

矩阵乘加：一行输出怎样算出来

去矩阵动画逐行核对。两行独立使用同一列输入，可以同时完成；每行内部累加该行的乘积。

Compute-bound / Memory-bound：算力与访存瓶颈

算术强度低且实际吞吐接近访存上限时，可以先检查搬运与复用。只比较两项资源下界和重叠条件，无法直接判定实际总耗时。

CUDA Graph：减少哪些执行提交开销

先看同一组 A → B → C：普通方式由 CPU 逐项提交；CUDA Graph 先记录操作和依赖、实例化成可重放的图，之后每轮提交整张图。上下时间线保持每个 kernel 的计算时长相同，让读者看到短 kernel 场景减少的是等待提交的空档。切换较长 kernel 后，普通方式也能提前提交后续工作，两条 GPU 时间线同时结束。两种情况都保留 CPU 与 GPU 的重叠，且图重放仍按新输入重新计算。首次准备有成本，需要通过重复执行摊薄。

FlashAttention：精确语义不变，重排 Attention 的 IO

普通实现可能把全部分数和 softmax 权重写到 HBM，再读回与 V 相乘。FlashAttention 改在片上对块计算，记下运行最大值、归一化量和加权和，遇到更大的分数时对旧贡献重新缩放。这样无需物化整个中间矩阵，仍得到相同的数学结果。浮点舍入可不同，稠密注意力仍有二次规模的计算。

术语速查
权重与激活
权重是模型参数；激活是本轮计算产生的中间结果。读取权重不是读取已经写好的回答。
算子 / kernel
算子描述要做的运算，kernel 是设备上执行它的一种实现；一个 kernel 通常不等于整个模型。
算力 / 带宽
前者约束单位时间能做多少计算，后者约束能搬多少数据；两种资源不能互相替代。
HBM / 片上 SRAM
HBM 容量大但访问成本高；SRAM 快但小。FlashAttention 的关键是把 Q/K/V 分块搬入片上，减少往返 HBM 的中间读写。
tiling / online softmax
tiling 把矩阵切成能放进片上的块；online softmax 用运行最大值和归一化量逐块合并，数学上与整段 softmax 等价，浮点运算顺序可产生舍入差异。
FlashAttention
一种精确 Attention 的 IO 感知实现：不改变 Q/K/V 公式或 softmax 数学语义，主要减少 HBM 读写和中间矩阵物化；稠密注意力的二次复杂度仍在，具体实现的 FLOPs 可因重计算而变化。
