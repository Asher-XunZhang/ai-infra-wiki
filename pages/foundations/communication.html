通信语义：Broadcast、Reduce、AllToAll、Send/Recv 与同步

从数据属于谁、如何组织、交给谁、何时可用四个问题，理解集合通信、点对点、单边访问与同步。

可单步操作原理与实现分开来源与教学边界

先看：TP、PP、DP、EP、SP 与 PCP/DCP：多卡怎样分工？

01

先问四件事：谁有数据、怎样合并、结果给谁、何时可用？

并行计算使不同进程各自持有一部分数据或计算贡献。通信语义给出大家共同遵守的结果约定，避免每段计算自行猜测该发什么、接到哪里。先决定正确结果，再选择实现该结果的算法与接口。

早期消息传递以进程之间的收发为基础；MPI 将常见协作模式标准化。NCCL 面向 GPU 提供通信实现。它们有重叠的操作，但接口范围、内存模型与完成方式不能直接等同。

先问四件事：谁有数据、怎样合并、结果给谁、何时可用？
操作／问题输入与结果用途或条件
分发与收集复制一份或按顺序收齐片段Broadcast、Scatter、Gather、AllGather
归约与扫描合并对应位置或 rank 前缀Reduce、AllReduce、ReduceScatter、Scan、Exscan
交换与点对点按目标重排或指定伙伴交接AllToAll、邻域交换、Send/Recv
单边访问发起方指定远端窗口位置Put、Get、Accumulate、CAS
同步与完成限定什么时候允许继续Barrier、完成事件、消费者依赖

02

复制、分片、收齐：为什么有四种不同操作？

完整输入可能只在一个进程，计算后的片段又可能散在各处。需要的是相同副本、不同片段、单方完整结果还是全组完整结果，决定了分发与收集的方向。

复制、分片、收齐：为什么有四种不同操作？
操作／问题输入与结果用途或条件
Broadcastroot [7,8] → 每方 [7,8]所有人需要同一份
Scatterroot [1,2,3] → [1] / [2] / [3]各自处理不同段
Gather[1] / [2] / [3] → root [1,2,3]只有 root 需要完整结果
AllGather[1] / [2] / [3] → 每方 [1,2,3]每方都需要全部片段
继续了解：不等长片段与存储代价

v 表示数量可以随来源或目标变化；如 [1]、[2,3]、[4]，不能假定每方贡献同样长度。count 与 displacement 共同确定数量和位置，图中选择紧凑排列；真实接口允许其他合法布局。

AllGather 的全量副本需要接收空间。若下游只在 root 使用结果，Gather 更符合所需布局；这不是无条件的速度比较。

03

相加与拼接不能互换，归约结果也不总要复制给全组

TP 的部分计算可能产生同一输出的不同贡献。归约按相同下标合并数值；SUM、MAX 等运算有不同数学含义。结果还要按后续计算的位置分配。

相加与拼接不能互换，归约结果也不总要复制给全组
操作／问题输入与结果用途或条件
SUM 示例[1,2,3] + [10,20,30] + [100,200,300]结果 [111,222,333]
Reduce上述完整结果只给 root其他 rank 的输入仍在
AllReduce每方获得上述完整结果每方后续都要使用
ReduceScatterRank 0 / 1 / 2 获得 111 / 222 / 333后续继续分片计算
继续了解：结果等价不等于执行过程相同

在相同运算与布局下，Reduce 后 Broadcast 的结果可等价于 AllReduce；ReduceScatter 后 AllGather 也能形成 AllReduce 结果。动画只解释输入输出，不声称库内部必按这个拆法实现。

浮点相加的顺序会影响舍入，树形和环形算法可能给出略有差别的数值；本课整数算例只用于看清语义。

AllToAll 和 AllGather 为什么容易混淆？

AllGather 将每个来源的同一段数据交给每个目标；AllToAll 中，一个来源给不同目标的块可以不同。用“来源为行、目标为列”的矩阵，才能看清数据重排。

AllToAll 和 AllGather 为什么容易混淆？
操作／问题输入与结果用途或条件
AllToAll源 i 的第 j 块 → 目标 j输出按来源组织；对角线为本地
AllToAllv每对来源／目标数量可不同，也可为 0双方数量与类型约定匹配
邻域交换仅沿通信拓扑定义的邻居边不与全部 rank 直接交换
Send / Recv源与目标配对交接不要求无关 rank 提交收发
继续了解：匹配与进度

MPI 使用通信上下文、源和 tag 等匹配消息；NCCL 点对点接口有自己的 peer、数量、类型和调用顺序要求。需要并发推进的 NCCL Send/Recv 通常成组提交，避免互相等候。

不等长只是语义需求，实际引擎可用专用 dispatcher、点对点或库接口实现。不要从 AllToAllv 名字直接推出某个 SGLang 版本采用了同名函数。

05

Scan / Exscan：为什么有人只需要前缀和？

当各 rank 产出长度不同时，要把结果放入一个连续区间，就需要知道自己之前总共有多少元素。全组总量不能直接告诉每个 rank 的起点。

Scan / Exscan：为什么有人只需要前缀和？
操作／问题输入与结果用途或条件
局部数量Rank 0 = 2，Rank 1 = 3，Rank 2 = 4总量 9
Scan · 含自身2、5、9各自结束位置
Exscan · 不含自身未定义、2、5应用另将 Rank 0 起点置 0

06

单边访问为什么仍需要窗口与同步？

已知远端位置时，发起者可以描述完整的一次读写，无需目标为每笔数据调用匹配 Recv。这把逐消息接收安排转成预先建立的窗口、访问权限和完成协议；单边不意味着远端完全没有准备或协调。

单边访问为什么仍需要窗口与同步？
操作／问题输入与结果用途或条件
Put本地 [7,8] → 远端窗口发起者是数据源
Get远端窗口 [7,8] → 本地发起者是接收方
Accumulate远端 5 加上本地 2 → 7按指定运算合入目标
CAS远端值等于期望值才写入新值；返回旧值比较与交换不可被拆成普通读写
继续了解：完成层次

以合法 passive-target 访问期中的 MPI 为例，Win_flush_local 确认发起侧完成，Win_flush 还确认相应目标侧完成。目标 CPU 的本地访问仍需遵守窗口内存模型和同步协议。不要将这种约定直接搬到任意 RDMA、GPU 或 NCCL 接口。

依据：MPI · Put · MPI · Get · Open MPI · Accumulate · Open MPI · Compare and Swap

07

异步传输为什么还要确认完成？

异步机制让提交线程继续工作，传输或计算稍后完成。因此要分别询问：调用是否返回、发送缓冲区是否可改、目标数据是否完整、消费者能否按正确顺序读取。不同接口的“完成”回答不同问题。

完成事件的保证范围
事件能说明什么仍不能推出什么
NCCL 调用正常返回（普通入队语义）工作已排入指定 CUDA streamGPU 操作已经完成
MPI 普通发送完成发送方可复用发送缓冲区接收方已经处理消息
MPI 接收完成接收缓冲区含有消息，可按契约访问匹配发送也已完成
Barrier 返回同组成员已进入该次屏障无关传输或 GPU 工作已完成
控制通知到达已知请求归属或目标地址KV 载荷已写完
继续了解：消费者的执行依赖

本课 NCCL 场景选择不同 GPU stream：通信 stream 记录事件，消费者 stream 等待相应事件后才读取。同一 stream 中的后续工作按该 stream 的顺序约束；主机要确认完成可使用相应事件或同步接口。

本课 KV 场景保留通知先到的例子：传输确认、请求匹配与消费侧依赖都满足后才使用。具体控制消息、可见性和生命周期约定见 SGLang 实现课。

08

哪些交接能并发，哪些必须等待？

语义说明最终结果；算法说明如何组织传输，例如 ring、tree；部署说明同机或跨机；互联与后端决定实际链路。数据直接在参与者之间交付；归约算式用于说明数值如何合并，不代表中央服务器，也不规定 NCCL 选择哪种算法。

不同通信对的独立交接可以重叠推进。例如 Scatter 中 root 发给 Rank 1 和 Rank 2 的分片，不要求前一份到达后才开始下一份。动画直接呈现数据从来源到目标的并发移动；实际算法不保证各份数据同时开始或完成。

真正的依赖仍需要保留：转发某个数据块要先收到该块，归约要取得所需贡献，消费者要等待相关结果可用。Ring 或 tree 算法可能划分多个阶段，同一阶段也可包含多条并行传输；归约与传输还可按块重叠。本课的算式演示只分解结果含义，不复现具体算法的时间安排。

同一 communicator 的集合调用需要遵守匹配与顺序约定。等长操作与 v 变体的数量要求不同；某个 rank 缺席或约定不匹配，不能当成一个可继续使用的正常结果。完成某次集合操作也不普遍等同于全组 Barrier。

接口边界：本课覆盖到哪里

NCCL 文档说明：同组内面向不同 peer 的点对点调用可以独立推进，需要并发推进的收发应合并提交；面向同一 peer 的调用仍按顺序执行。各 rank 对集合调用遵守一致的调用顺序，与内部载荷是否并发，是两个不同层次的要求。

本课为常见通信语义族提供演示，不枚举所有库函数、数据类型与拓扑。非阻塞、持久化调用与普通调用往往共享结果语义，但启动和完成协议不同；本课用完成时间线解释其共同问题，不声称复现各 API 的完整状态机。

MPI 的 v/w 变体、inter-communicator、派生数据类型与任意邻接图还有更多约定；本例限单组、整数、紧凑缓冲区。NCCL 与 MPI 的接口不是一一对应。实际 SGLang 调用以实现课固定提交为准。

依据：集合通信的结果约定 · NVIDIA NCCL · NCCL：点对点通信与并发推进 · NCCL：分组与调用顺序

试着解释

收到“数据将写入块 B”的通知，就能读取 B 吗？

展开解释

不能。还需确认载荷完成并满足消费者的同步与匹配条件；控制消息只说明归属和目标，不代表写入已经完成。

术语速查

展开：Rank、Root、Count、RMA 与 Stream
Rank / Communicator
Rank 是通信组内参与进程的编号；communicator 提供组与通信上下文。本例用 P0、P1、P2 标识进程，rank 取 0、1、2。
Root（根参与者）
集合操作指定的源或结果接收者。★ 表示本例 root；它是组内 rank，不必为 0，也不是固定服务器。
Collective（集合通信）
通信组成员共同遵守的输入输出约定。All 表示全组相关的结果语义，不表示某种物理全连接网络。
Reduction（归约）
按指定运算合并对应位置，如 SUM 求和、MAX 取最大。Gather 的拼接不做这种算术。
Count / Displacement
count 表示元素数量；displacement 指定片段在缓冲区中的位置。v 变体允许按参与者指定不同数量，图中采用连续紧凑布局。
Send / Recv
发送与接收。点对点通信由源和目标配对；MPI 还使用 tag（消息标签）和通信上下文匹配。
RMA / Window
Remote Memory Access，远端内存访问。window（窗口）是进程允许远端访问的内存区域；单边操作仍需建立窗口、权限和合法同步。
Stream / Event
GPU stream 是有序执行队列；event 是用于记录完成、建立依赖的事件。同设备不同 stream 不自动按 CPU 调用次序建立消费依赖。

对照算例，回看机制与取舍

Broadcast / ScatterGather / AllGatherReduce / AllReduce / ReduceScatterAllToAll / AllToAllvSend/Recv 与邻域交换Scan / ExscanPut / Get / 原子更新Barrier / Completion

Broadcast / Scatter：复制同一份，还是分发不同片段？

三个 rank 需要同一份 [7,8] 时用 Broadcast；三个 rank 分别负责 [1]、[2]、[3] 时用 Scatter。切换 root 可以看到源改变，结果约定不变。分发不能代替广播，否则每方只得到部分数据。

Gather / AllGather：完整结果需要留在哪里？

Gather 将各方片段收给 root；AllGather 让每方都收齐。后者增加结果副本和接收存储，只有后续每方都需要全部数据时才有意义。Gatherv / AllGatherv 在片段不等长时还需各方约定数量与放置位置。

Reduce / AllReduce / ReduceScatter：归约后谁需要结果？

本例输入 [1,2,3]、[10,20,30]、[100,200,300]，SUM 得 [111,222,333]。Reduce 仅交给 root；AllReduce 每方一份；ReduceScatter 分别交出 [111]、[222]、[333]。后续只处理局部分片时，不必让每方都保留完整向量。

AllToAll / AllToAllv：按目标重新组织数据

i→j 表示源 rank i 发往目标 rank j 的块，b 表示同一对的第二个元素。每个目标从不同来源收集自己的块；同 rank 的对角线块属于本地数据。AllToAllv 允许某一对为零个、另一对为多个；发送数量必须与对端接收约定相容。MoE 专家派发可产生这种不均匀交换需求，但实际引擎未必调用同名 API。

Send/Recv 与邻域交换：哪些参与者需要互相交接？

PP 相邻阶段只需要交接相应激活，可用点对点表达；邻域集合通信则按预先定义的图交换。本例线形邻接 0↔1↔2，不把 0 和 2 当直接邻居。逻辑邻居不一定在物理机器上相邻。

Scan / Exscan：前缀累计量有什么用？

局部数量为 2、3、4 时，Scan 得到截至自身的累计量 2、5、9。Exscan 得到此前各 rank 的累计量：Rank 1 为 2、Rank 2 为 5；MPI 不定义 Rank 0 的接收结果。应用可单独将 Rank 0 的存储起点设为 0，用这些起点安排变长结果。

Put / Get / 原子更新：指定远端位置的访问

Put 将本地载荷写到远端窗口；Get 从远端窗口取回本地。Accumulate 将数值按运算合入目标；CAS 比较旧值和期望值，匹配才替换，并返回旧值。本例只操作一个整数，不能理解为任意多个地址构成一个事务。

Barrier / Completion：会合、传输完成与可用

屏障让先到者等同组成员进入；它不自动完成其他独立传输。异步提交返回、发送缓冲区可复用、接收内容完整、消费侧依赖满足也不是同一个条件。读图时要指出具体哪个事件保护下一次读取。

相同三组输入归约后，只有一个参与者需要完整结果，应该选哪一种语义？

自测与解释：相同三组输入归约后，只有一个参与者需要完整结果，应该选哪一种语义？

Reduce 对应“归约且只交给 root”。AllGather 保留各方元素，不执行归约；Barrier 只有会合条件，不产生用户张量结果。
