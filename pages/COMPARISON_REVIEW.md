## 保留项及理由

| 课程/模块 | 决定与理由 |
| --- | --- |
| Tokenization、Embedding | 保留表示转换与查表过程；不虚构一个合法的“不做分词/Embedding”优化基线 |
| 自回归生成、逐层前向 | 保留输入、Prefill/Decode、选择和输出的因果链；缓存收益由 KV 课解释 |
| Attention、因果遮罩、完整模型层 | 保留数值贡献与可读取范围；不把移除正确性约束当成性能优化方案 |
| 固定/连续批处理 | 已有同一请求集逐轮成员对照，保留并回归，避免重复新增 |
| GPU 算力/带宽、CUDA Graph | 已有同工作量资源界限及同依赖时间线，包含收益不明显的条件；保留 |
| 通信原语 | 已有输入、所需输出、参与者和完成语义；作为并行成本的解释入口，不宣称“采用通信更快” |
| 取消与安全收尾 | 是生命周期正确性，保留在途、通知、完成和归还区分 |
| 性能指标 | 保留计时端点与统计口径；减少失败样本后的 P95 变化不是优化收益 |

## 技术依据与边界

所有对照数据来自本仓教学模型或明确标注的新教学假设，不引入论文的性能倍数。以下是概念依据，训练框架文档只用于解释结构，不作为 SGLang 推理配置支持证明；各实现课的固定源码基线保持独立。

- TP 的矩阵分解：[NVIDIA Megatron-LM](https://research.nvidia.com/labs/adlr/MegatronLM/)。
- PP、EP、SP 的对象与边界：[Megatron Bridge Parallelisms Guide](https://docs.nvidia.com/nemo/megatron-bridge/latest/parallelisms.html)、[Megatron Core CP](https://docs.nvidia.com/megatron-core/developer-guide/latest/user-guide/features/context_parallel.html)。SP 的基线为 TP 内逐 token 区；布局通信应连同原 TP 的 collective 比较，不能笼统宣称凭空新增两次通信。
- PCP/DCP 的适用目标与通信成本：[vLLM v0.11.2 Context Parallel](https://docs.vllm.ai/en/v0.11.2/serving/context_parallel_deployment/)。本课 PCP AllGather 示例不保证每卡 KV 驻留减半；DCP 简化模型只展示历史位置分片与加权合并。
- KV 缓存：[Hugging Face 缓存说明](https://huggingface.co/docs/transformers/main/en/cache_explanation)；分页：[PagedAttention 原论文](https://arxiv.org/abs/2309.06180)、[vLLM 的逻辑块与物理块映射说明](https://vllm.ai/blog/2023-06-20-vllm)；前缀：[vLLM v0.11.2 APC](https://docs.vllm.ai/en/v0.11.2/features/automatic_prefix_caching/)。
- 组批：[Triton 动态组批](https://docs.nvidia.com/deeplearning/triton-inference-server/archives/triton-inference-server-2680/user-guide/docs/user_guide/batcher.html)、[Orca](https://www.usenix.org/conference/osdi22/presentation/yu)、[vLLM v0.11.2 Chunked Prefill](https://docs.vllm.ai/en/v0.11.2/configuration/optimization/)。
- 角色分离：[DistServe](https://arxiv.org/abs/2401.09670)；推测解码：[Fast Inference from Transformers via Speculative Decoding](https://arxiv.org/abs/2211.17192)。
