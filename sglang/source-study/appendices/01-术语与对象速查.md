## 3. 生成数据与缓存状态

| 名称 | 人话解释 | 容易混淆的边界 | 详解 |
| --- | --- | --- | --- |
| token ID | 模型 tokenizer 词表中的离散编号 | 不等于一个字、一个词或一个向量 | [文本到输出](../00-foundations/03-从文本到Token再到模型输出.md) |
| embedding | 输入 ID 对应的初始数值向量 | 不等于下一 token 概率 | 同上 |
| hidden states | 经过模型层更新的内部表示 | 不等于所有历史 KV，也不等于原文字符串 | 同上 |
| logits | 词表候选的分数 | 未必是归一化概率，更不是事实正确性证明 | 同上 |
| sampling | 按请求规则从候选分布选择输出 token | 模型算分和采样规则应分开追踪 | 同上 |
| EOS / stop | 请求停止判断使用的 token 或文本相关条件 | 必须看实际配置与检查次序，不只认一个参数名 | 同上 |
| Prefill | 处理已给输入、建立状态并预测后续 token 的阶段 | 可以分块，也可能复用已有前缀 | [两阶段与 KV](../00-foundations/04-Prefill与Decode及KVCache入门.md) |
| Extend | 给已有序列补算新一段；当前代码的模式分类 | `is_extend()` 覆盖不止首次 Prefill | 同上 |
| Decode | 普通生成中把刚生成的 token 继续送入模型 | 当前输入与本轮新输出相差一个预测位置 | 同上 |
| Q / K / V | Attention 中的查询、被匹配表示与被汇集表示 | 是张量角色，不是自然语言的问答或数据库记录 | 同上 |
| KV Cache | 保存相应层历史位置的 K/V 状态 | 缓存数据、前缀索引、分配策略是不同职责 | 同上 |
| KV pool | 提供实际 K/V 或其他模型状态存储的池 | pool 总容量不同于某请求当前内容长度 | 同上 |
| prefix match | 找到可复用的兼容前缀状态 | 逻辑命中不自动表示 GPU 数据已就绪 | 同上 |
| `kv_committed_len` | 当前请求 KV 账本维护的提交边界 | 普通 allocation 在 forward 前推进，不能单独当作 GPU 完成信号；释放后也可能保留旧值 | [02-04 逐轮账本](../02-request-lifecycle/04-一次Prefill到多轮Decode.md) |
| `kv_allocated_len` | 当前请求 KV 账本记录的已分配长度 | 可能包含预留/页对齐，不能全部看成有效内容 | 同上 |
| `cache_protected_len` | 已由树缓存保护/管理的前缀边界 | 请求私有后缀与共享前缀不能使用同一回收判断 | 同上 |

## 4. 时间、吞吐与单位

以下口径与限制详见 [00-05](../00-foundations/05-吞吐延迟与显存的基本账本.md)。

| 名称 | 人话解释 | 必须附带的条件 |
| --- | --- | --- |
| TTFT | 开始计时到首个有效输出的延迟 | 客户端/服务端、是否流式、首输出事件定义 |
| ITL | 相邻输出 token 的间隔；工具可能观测的是 chunk | chunk 是否聚合、是否有重新分词调整 |
| TPOT | 首输出后按后续 token 数分摊的时间 | 本版 serving 汇总为 `(E2E - TTFT)/(N - 1)`，N > 1 |
| E2E | 请求开始到结束计时的总延迟 | 观测位置及尾部协议处理是否包含 |
| 请求吞吐 | 单位时间成功完成的请求数 | 输入/输出分布、失败数和窗口 |
| 输出吞吐 | 单位时间产出的统计输出 token 总数 | 全程还是稳定窗口；不等于每用户速度 |
| P50/P95/P99 | 样本分布的相应分位数 | 样本量、筛选口径和分位数算法 |
| KV bytes/token | 一个物理位置跨相应层的 KV 数据量 | 模型状态类型、head 数、维度、dtype、分片与辅助开销 |
| KiB / GiB | 分别为 1024 与 1024³ 字节 | 区别于十进制 KB/GB |

## 10. 普通调度循环与空闲

| 名称 | 人话解释 | 容易混淆的边界 | 详解 |
| --- | --- | --- | --- |
| dispatch_event_loop | 选择实际调度循环的模块级函数 | 不是按请求选择 batch，也不属于 Scheduler 方法 | [03-01](../03-scheduling/01-NormalEventLoop与调度主循环.md) |
| normal event loop | 同轮按输入、选批、执行、结果/空闲顺序调用的 Python 循环 | 不等于单卡模式，也不保证每个底层 GPU API 阻塞 CPU | 同上 |
| forward_ct | Scheduler.run_batch 的调用计数 | 不等于 while 轮次、Decode 次数或输出 token 总数 | 同上 |
| no-batch stall | 本轮没有可执行批，但仍有未完成工作 | on_idle 会进入非完整空闲分支，不走其末尾 sleeper | 同上 |
| is_fully_idle | 综合请求、批次与已启用功能状态的空闲判断 | for_health_check 分支口径不同，不是通用正确性证明 | 同上 |
| after_idle_gap | 本次执行之前是否经过无 batch 分支 | 源头标志在完整空闲判断前设置，范围比真正休眠宽 | 同上 |
| IdleSleeper | 在满足条件时等待输入 socket 可读的组件 | poll 超时参数不是每个请求固定增加的延迟 | 同上 |
| scheduler stage wall time | 按当前调度阶段累计的墙钟时间 | 不等于 CPU 利用率或 GPU kernel 耗时 | 同上 |

| lookahead / 多算结果 | 旧结果提交前已经推进的下一批工作 | 不保证产生更多有效输出；已结束请求可跳过追加 | 同上 |

## 15. 回撤、延迟接纳与停滞诊断

| --- | --- | --- | --- |
| check_decode_capacity | 分配器判断下一步容量，代表实现先尝试回收缓存 | 不是纯计数查询，也不是 GPU 总显存检测 | [03-06](../03-scheduling/06-回撤背压饥饿与调度排障.md) |

| retraction_policy | 决定哪些成员优先保留的 length/priority 策略 | 返回顺序与实际 pop 回撤顺序相反 | 同上 |
| retraction_count / retracted_stain | 累计回撤次数与曾回撤标记 | is_retracted 会在再次准备执行时清除，历史标记保留 | 同上 |

| MinFreeSlotsDelayer | 本地等待足够请求空位再接新 Prefill | 独立于 PrefillDelayer，没有共用其轮次超时 | 同上 |
| SchedulerInputBlocker | 暂存原始输入，解锁屏障满足后释放 | 不等于 _engine_paused；UNBLOCK 收到不等于已派发 | 同上 |

| pool invariant / watchdog | 分别观察资源分类账与特定计数是否变化 | 计数平衡不证明无竞态；无报警不证明每个请求前进 | 同上 |

## 16. 请求位置、物理槽位与页

| 术语/对象 | 人话解释 | 关键边界 | 对应正文 |
| --- | --- | --- | --- |
| 请求行 r | 每条持 KV 请求在地址表里的行 | 与 rid、batch 行 b、物理槽位 s 分开；行 0 保留 | [04-01](../04-kv-cache/01-请求视图物理槽位与分配器.md) |
| `req_to_token[r,t]` | 请求逻辑位置 t 对应的普通池槽位 | 保存整数地址，不保存词表 ID 或真正的 K/V 向量 | 同上 |
| `req_generation` | 一行每次重新分配时增加的代次 | 计数存在不代表所有异步读者都检查它 | 同上 |
| `out_cache_loc` | 本轮新增 token 的写入地址列表 | 长度是新 token 数，不是新页数或完整历史长度 | 同上 |
| 页号与槽位 | P 大小时，槽位 s 属于页 s//P、偏移 s%P | 页 0 含 P 个保留槽位；不是只保留槽位 0 | 同上 |
| 尾页余量 | 请求已有最后一页中尚未用到的位置 | 合法持有者可续写；不能把他人共享页余量自动占为己有 | 同上 |
| `MHATokenToKVPool` | 普通池各层真实 K/V 存储 | 静态 NHD 形状与其他布局/模型分开；free 页号不销毁整个 tensor | 同上 |
| packed 读索引 | 按请求长度拼接的历史地址 | `kv_indptr` 分界与 batch 行、请求行必须一致 | 同上 |
| `KVIndexTranslator` | 后端取得读地址的统一入口 | 本篇普通池不翻译地址；统一池的虚实映射另讲 | 同上 |
| 释放暂存与 free group | 前者延后合并空闲数组，后者暂存一组待 free 地址 | 都不能仅凭名称当作设备完成事件 | 同上 |

普通 Prefill 尚未结束时也可能把前缀交给树并持锁；结束再解除锁和释放尾页。请求行、缓存所有权与 GPU 使用期限不能合成一个“已释放”状态。

## 17. 压缩前缀树、锁引用与淘汰

| 概念 | 人话解释 | 必须保留的边界 | 对应正文 |
| --- | --- | --- | --- |
| 传统 RadixCache / 默认选择 | 传统 Python 树适合拆解基本机制；该基线默认选择链最终进入 Unified | 先确认实际 cache 类，不把传统实现细节视为所有服务默认行为 | [04-02](../04-kv-cache/02-RadixAttention与前缀匹配.md) |
| RadixAttention 层 | 把模型 q/k/v 与 ForwardBatch 交给 Attention 后端的层接口 | 不在 forward 中遍历本文的 Python 前缀树 | 同上 |

| key limit | 调用者允许本次最多比较多长 | 上限、页对齐、实际公共长度分别约束命中 | 同上 |
| match 中的分裂 | 为落在段内的公共前缀建立新边界 | 运行时查询会改树；复制索引不增加同等数量的真实 KV | 同上 |

| protected / evictable | 树中受锁保护与未受锁保护的 token 容量 | 不按共享请求次数重复算，也不等于 allocator 已空闲容量 | 同上 |
| `evictable_leaves` | 当前可直接淘汰的无锁叶节点集合 | 无锁内部节点先等其子路径移除；总可淘汰量不等于叶子数量 | 同上 |
| 去重交接 | 保留树采用的地址，释放独占重复槽位并改写请求表、迁移锁 | 裸 insert 不完成全部所有权交接 | 同上 |
| SLRU 的 protected 段 | hit_count 达阈值后在候选中后淘汰 | 与 lock_ref 保护不同，仍可能被淘汰；hit_count 也不是查询总数 | 同上 |

## 19. Unified 组件与混合状态交接

| UnifiedRadixCache / TreeCore | 前者协调请求与池，后者组织共同树拓扑和组件 hooks | 统一树、树 backend 和统一内存池分别选择 | [04-04](../04-kv-cache/04-UnifiedRadix与混合状态组件.md) |

| cache / buffer_only | 常驻主机缓存 / 操作中转缓冲区 | 分配、占用计量、插树与准入采用路径不同 | 同上 |

## 68. 综合案例中的输入、状态与测量身份

对应 [12-05 综合案例](../12-extensions-and-capstone/05-从需求到源码与验证的综合案例.md)，将缓存、调度和实验放到同一条 R1/R2/R3 主线上。

| 名词 | 人话解释 | 本案例边界 |
| --- | --- | --- |
| 最终输入身份 | 模板处理后的 IDs 与相关 namespace | 相同文本或会话 ID 不自动证明可复用 |
| 本案例完成交接的 KV | 完成本轮计算并交接给缓存的状态区间 | 普通生成最后一个输出尚未自动获得自己的 KV；单看 kv_committed_len 数值不证明设备完成，见第 3 节 |
| 唯一路径占用 | 共享前缀只计一份的保留状态 | 不是并发峰值、真实显存或准入预算 |
| 冷态/暖态 | 指定测量起点的缓存状态 | 发出 flush 请求不等于清理成功 |
| 开放到达流量 | 按预先确定的时间送请求 | 不等于上轮完成后才能构造下一轮的闭环 |
| 运行拓扑 | 真正启动的 rank 及进程关系 | 模拟入口把各并行维度固定为 1 |
| 被建模拓扑 | 交给预测器的目标部署参数 | 写 TP=8 不证明进行了 8 卡通信 |
| Replay 回退 | 查询不到同形 batch 时的替代时间 | 默认可为零，必须报告覆盖率 |
| 模拟 completed | 模拟统计中的计数 | 当前 is_complete 恒真，需额外核对真实终态 |

## 69. 最容易混淆的四组关系

1. **可访问资源与控制其生命周期。** 模型层能读写 KV，不表示它拥有请求准入与缓存淘汰的全部策略。
2. **通知与完成。** 收到消息或 Event 被设置，只说明应检查相应状态，不能直接证明远端、GPU 和清理全部完成。
3. **逻辑长度与物理占用。** token 已知、KV 已提交、槽位已分配和 pool 已保留分别计数。
4. **测量值与系统真相。** 指标只覆盖它的观测点、样本和时间窗口；模拟数值、教学算术与真实运行证据应分开。
