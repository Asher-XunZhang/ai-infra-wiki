# 精简前端交接

按任务填写下面三项即可，删去无关字段。运行配置由调度方核对，已加载的项目规则不在每次提示词中重贴。

> **目标**：请在〈页面/功能〉实现〈读者可观察的结果〉，重点解决〈当前问题〉。你主导方案、实现与自测，完成后返回实际预览和简短验证结果。
>
> **必要边界**：〈本任务必须保留的行为、事实或文件〉；仅本地修改，保留已有工作。若本次只授权审核，将目标改为交付可审查方案，不实施。
>
> **资料入口**：〈相关实现入口〉；〈Codex 已核对的事实/算例及固定源码锚点〉；〈必要的参考图或测试入口〉。按需读取相关部分。

技术条件多时单独提供资料索引，不把所有资料粘进指令，也不要求无差别读完所有 Skill。不要预先写好视觉方案、逐步操作命令或要求反复汇报；缺少影响正确性的事实时再补充。

## 调度方在本地记录

workspace、模型版本与 Max、任务阶段、会话/PID、交接前文件状态、预算检查结果。按本 Skill 管理后台执行、浏览器清理与独立验收；这些管理信息不必每轮重复发给实现者。

长任务在自然交付点保存简短进度：已完成、关键决策、剩余问题与证据路径。已获批实施不额外要求中间方案审批。

## 返修

一次汇总已发现的缺陷：复现操作、实际/预期结果、代表截图或失败断言。说明需要修复的结果，具体修复方法由 Harness 决定。用短检查点通过受管工具开新批次，不能为了“连续返修”无限追加。

布局或动画遮挡问题补充：场景／参数、播放位置、视口宽高、主题和缩放状态，以及看不清的身份、文字或计算关系。按项目教学 Skill 的 [布局与过程可读性](../../sglang-interactive-learning/references/visual-readability.md) 验收，说明共享影响范围；无需把整份规则粘进交接。

## 换会话时的检查点

- 已批准目标、关键决策及必须保留的约束。
- 当前文件状态和修改清单；原有脏工作区不可回滚。
- 已运行的验证与对应文件版本，未解决问题的最小复现。
- 下一批目标、必要资料入口、本地预览地址。
- 前一执行者退出及浏览器清理情况、仍保留的服务。

只保留仍有效的信息；新会话核对当前文件后继续，不重做已完成的内容。
