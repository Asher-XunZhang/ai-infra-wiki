# 机制场景与验收样例

以下是教学设计模式，不是任意版本 SGLang 的实现事实。具体行为、合法组合和参数意义必须回到所选公开源码基线。数字均需明确为教学示例或实际测量。

## 从知识点设计画面

先用普通语言写下读者应该能回答的问题，再为难以理解的转换设计画面。不要从“使用哪种 tween”“做几张卡片”开始。

一条最小算例应有明确输入、稳定参照、关键操作和可核对的结果。设计时可用下面四项作工作草稿，不必把草稿字段变成页面表单：

- **缺口**：初学者在哪一步必须靠猜？是术语、对象对应、计算方法，还是完成条件？明确必要先修，不在 SGLang 实现课重复整章基础知识。
- **参照**：哪些内容固定下来能减少记忆负担？例如物理页位置、P/D 职责、完整调用地图、上轮客户端输出。
- **变化**：本步真正改变什么，发生条件是什么？片段拆分、按编号查表、加权贡献、写入格子、建立引用、等待条件满足，都有不同的视觉动作。
- **解释**：中途暂停能否辨认当前工作？完成后能否从画面证明结果？选择一个边界条件，让读者先预测再操作验证。

### 用机制选择图形，而不是用模板限制机制

每个子机制分别确认完整对象、切分或复制的维度、局部操作及汇总规则。可以借鉴可靠教学资料的表达顺序，需核对技术范围并标注参考；借鉴呈现方法，不直接套用训练流程、设备限制或性能结论。

- **TP**：先画两个乘数的矩阵、形状与行列含义，用一个输出元素展示点积；再标切分轴，追踪矩阵分块到设备，展示局部乘积。按语义拼接或逐元素求和，与未切分结果核对。只写数组和局部结果会省略关键切分过程。
- **PP**：从完整模型层链说明 stage 划分，再用时间格表现 microbatch 交错、激活交接和气泡。
- **DP**：画相同的完整模型副本和不同请求的独立路径；不添加推理场景没有的输出求和。
- **EP**：用 token—专家路由关系、派发和按原 token 归位表达稀疏选择；专家放置、热点和路由权重需要可见证据。
- **SP / CP**：保留张量维度或 Attention 可见范围，明确序列分片、读取依赖、布局转换与合并；不能仅让缩写卡片跨 GPU 移动。

这些是选图依据，不是必须复用的布局。静态结构、逐格计算与连续移动可以组合；只在对象确实发生位移、复制或布局转换时使用移动。中途暂停时仍应能认出原始输入、当前操作和去向。

### 从成熟教学图提炼独立动画

设计或重做概念动画时，先查阅相关成熟教程，实际查看图像、动图的关键帧或交互过程。记录原文链接、作者或机构、读取时间、媒介类型，以及它如何解释当前难点；静态图的布局可以借鉴，但不能把未观察的播放过程称为动画参考。优先使用原作者、官方文档、论文作者的材料核对事实，参考表达不等于引用其实现或性能结论。

从参考中提取对理解有效的部分，例如完整输入、切分轴、形状标注、固定参照、来源颜色和结果落点。不要照搬全部流程或外观；图中省略的参与者、结果副本及前提，应按当前学习目标补清楚。页面记录简短来源与借鉴点，不把研究笔记全铺给初学者。

先用一句话写出“初学者看完应立即明白什么”，再列出缺少后会改变概念含义的核心信息。核心信息在画面中直接可见，关键转换连续呈现；非重点降低视觉权重、简短标注或移到展开说明。不要要求读者先读长段说明、认识辅助视图或打开折叠区，才能理解主动画。削弱细节不能削掉关键区别：例如 AllGather 必须看出不同输入被拼接、每个 rank 都得到完整结果；AllReduce 必须看出对应位置的值被归约、每个 rank 都得到归约结果。物理路由可以不展开，这些核心行为不能省略。

复合图先按学习问题拆解。每个概念有自己的最小输入、必要动作和结果，可直接进入并独立播放；不用让读者先走完其他概念的动画。共享控件与数据模型即可，不要求每个概念新建一页或一套播放器。单概念也可以包含多个必要步骤，不能为了拆分再省略因果过程。

以矩阵并行教学图为例：

| 独立演示 | 保留的行为 | 与综合实例的关系 |
| --- | --- | --- |
| TP | 完整 X、W 及形状 → 切分轴 → 各分片局部乘法 → 按当前分法求和或拼接 | 讲清整层如何分工，通信术语链接对应演示；不把某次广播或收集画成所有 TP 实现的必经步骤 |
| Broadcast | root 上同一份数据复制到所有参与者，root 保留数据 | 不夹入矩阵乘法；来源相同的副本保持对应颜色和标识 |
| Scatter | root 的不同片段分别交给对应参与者 | 与复制完整数据区分；标明片段身份及目标，不添加 TP 计算 |
| AllGather | 各 rank 的输入按 rank 顺序组成完整结果，每个 rank 都得到结果 | 保留片段颜色与拼接轴；不只画一份中央结果，也不进行求和 |
| AllReduce | 各 rank 同一坐标的贡献按所选运算归约，每个 rank 都得到结果 | 用小算式说明新值来源；不把求和画成拼接，不预设中央归约节点 |

**来源配色。** 先选稳定的来源单位，例如原始张量的分片或输入所属 rank，再建立图例。同一片数据在切分、复制、传输和拼接后保持颜色对应，不能随所在设备改变颜色。原件、切片、副本配合名称或坐标区分；颜色不是唯一识别手段。状态使用边框、文字等另一种编码。求和、乘法产生的新值需显出输入贡献或对应算式，使用明确的结果编码，不能把新值误画成某一来源的未改变副本。复制源是否保留按操作语义及示例设定表达，不能为腾位置让它凭空消失。

**独立动作并发。** 先辨认真实依赖，再组织时间线：同一阶段内无依赖的复制、交换或局部计算共同推进；后续消费仍等待它需要的输入。用间距、不同弧线、固定行列或简化对象解决交叉遮挡，不用错峰播放创造串行含义。若当前课专讲 ring 等算法，其轮次按算法依赖呈现；概念语义图不引入这类额外阶段，也不把同时播放当作真实链路同时完成的证据。

**节奏按理解难点分配。** 首次展示切分轴、一个点积、同坐标归约、拼接顺序或就绪条件时放慢或短暂停留，让输入、操作与结果可以对照；已经解释的重复副本与相同计算可并发、缩短或概括。最终画面保留结果和必要原因，不用读者抢在消失前阅读。共享播放器可以有默认时长，但每个概念要按关键动作安排相对时长，不能机械套用统一节拍，也不能靠加长无信息的位移充当讲解。

速度使用带倍率读数、可键盘操作的滑块；默认 1× 对应该动画选定的基础节奏，沿用项目已确认的整体速度体验。滑块对整条时间线同比例缩放，保持并发关系与相对节奏；播放中调整不重置、不跳步。教学停留和播放秒数不代表真实计算或通信耗时，图中的仿真时间、事件顺序和结果不随播放倍率改变。减少动态效果模式可用静态对应关系和步进保留同样的解释。

### 从结果反推必需的解释

复盘一张图时，不先问“还能加什么动画”，而是问“读者需要猜哪一步，才能理解这个结果”。围绕实际缺口补齐因果，不按固定模板增加阶段。以下规则按当前概念是否涉及对应关系选用。

| 图中表达的内容 | 必须让读者看见 | 应排除的误导 |
| --- | --- | --- |
| 数值、比例、长度或数量 | 输入、单位、对应关系与产生结果的运算；必要时先用可核对的小例子展开 | 只有最终数字或长短条，却不知道数字如何得到；把身份编号、绘制进度和实际数量混为一谈 |
| 位置、归属或状态变化 | 改变前后的同一对象，触发变化的条件，以及变化后获得或失去的能力 | 用移动暗示不存在的传输、归属转移或完成；只改标签却省略决定下一步的条件 |
| 等待、先后或重叠 | 当前工作、未满足的依赖或资源条件，以及解除等待的事件 | 为讲解方便把独立动作串行化；把某一种等待原因泛化为所有空档的原因 |
| 两种方案或条件的对照 | 共同输入、观察范围、计量尺度，发生改变的因素和保持不变的部分 | 同时改变多个因素却把差异归因于一个机制；为突出优化而偷偷减少必要工作或删掉依赖 |

**表示方式服从问题。** 先判断要解释的是数值如何形成、对象如何对应、状态何时改变，还是事件何时允许发生，再选运算展开、空间布局、状态图或时间线。若改变颜色、增加运动仍无法回答这个问题，应重选表示方式。一个课题可以有多个独立问题，不必用一张复合图同时承担全部解释。

**声明图形究竟表示什么。** 区分逻辑关系、资源需求、教学执行模型与实际运行记录。位置、距离、面积和条块长度只有在定义了单位或比例时才表达数量；连线和播放先后不能自动成为真实传输或依赖的证据。多个独立估算不能直接拼成执行时序，事件顺序也不能直接读成耗时。

**让适用条件影响结果。** 解释优化或策略选择时，指出改变的是哪项成本、限制或能力，以及哪些必要工作仍然存在。若收益依赖特定条件，优先选择一个有区分力的条件切换，让读者能预测收益增强、减弱或消失的原因；不机械地给每个概念添加成功／失败两套场景。涉及准备与复用时，分清一次性成本、每次仍需付出的成本和被复用的对象；不能仅用“更少步骤”暗示“整体更快”。

**用解释能力验收。** 隐去大段旁白后，读者应能根据画面回答结果从哪里来、为什么此刻能或不能继续、改变一个条件后什么会变。数值守恒和依赖检查验证语义，关键中间态的实际观察验证表达；两者不能互相替代。若答案只能从图外文字获得，补的是图中的因果关系，而不只是更长的说明。

### 固定参照，显露因果

| 知识细节 | 合适的连续表达 | 应避免的捷径 |
| --- | --- | --- |
| 原文 → token → ID → embedding | 原句逐渐拆成片段，片段对应词表条目，ID 索引向量行，再保持输入顺序；解释数值输入与可复用词表的作用 | 最后一屏直接列 ID；把 token 固定说成一个汉字；把 ID 数值大小画成语义强弱 |
| 同一个 token 多次出现 | 区分“词表条目相同”和“出现位置不同”；同一 ID 查同一行初始向量，位置和后续上下文另有作用 | 重复展示表格行却暗示词表存在多个相同 ID；用不真实的分词结果配合演示 |
| 自回归生成与历史 | 保留客户端文字，画出模型侧新输入，经过计算后才追加历史；下一组候选来自新的计算 | 反馈时从客户端把文字搬走；采样一个输出就立即给 KV 加一格 |
| Attention 的数值混合 | 同时看见 Q、允许的 K、点积示例、归一化权重、V 各维贡献及求和；未来位置在对应行遮住 | 只移动 Q 卡片；只显示最终权重；把权重直接称为语义重要性 |
| KV 重算与复用 | 相同输入、相同新增位置并排同步比较；分别标明读取历史和新算位置 | 让读者切换条件后凭记忆对照；把少算若干位置等同于同比例提速 |
| 连续批处理 | 等待区、固定的本轮执行位置、每条请求的 token 序列；同步生成，完成后退出，再按条件补入 | 整张 batch 换卡；仍在执行的请求被无故挪动；把教学执行位置称为真实 GPU 硬件槽 |
| 逻辑 KV 与物理地址 | 物理页固定，逻辑位置通过映射找到槽；先预留地址，再写入；尾页空位与空闲整页分开 | 为保持逻辑顺序移动物理页；把映射线当数据副本；预留完成即显示所有数据可用 |
| 模型执行与图重放 | 固定职责地图，明确 ID、向量、Attention 结果、logits 与采样的不同类型；图桶分别标出真实行和 PAD | 两个框每步换名字；同一个无标签光点贯穿所有数据类型；把 PAD 当真实请求或旧答案缓存 |
| 调度准入 | 画出请求的命中历史、新输入及不同预算；排序、临时检查、提交计划分开；最终保留拒绝理由 | 只看排队名次；把计划预算当物理写入；最终空计划清掉造成拒绝的比较式 |
| 容器与对象 | 固定本地 Req，连线建立或解除引用；同时持有时明确多条引用；跨进程对象另行标注 | 请求卡片在容器间迁移，掩盖并存引用；把各 PP rank 的本地对象画成同一个 Python 对象 |
| P/D 交接与释放 | P/D 固定，元数据、KV 载荷、首个 token 分开；源端完成、目标可用、本级资源收尾分别满足条件 | 一条“完成”箭头代表全部状态；通知到达等同载荷可用；本级释放等同 D 已能运行 |

这些是表达选择，不是必须照抄的布局。数值比较适合条形或表格，依赖与等待适合时间格，引用适合关系图；有明确意义的静态图可以保留，不强行给每个节点加运动。

### 连贯性不只指位移

从旧值推导新值时，画出必要的对应关系、计算或贡献，不用淡入结果掩盖转换。对比两种机制时，尽量固定输入、单位和观察范围，只改变本次讨论的条件。图中的持续存在、空位、遮罩和等待也必须有语义。

同一对象保持身份；复制、派生值和引用分别表示。客户端文字的保留、源端 KV 在传输期间的保留、同一个 Req 的多处引用，都是机制的一部分，不是视觉冗余。连续动画不能凭空暗示内存搬移、串行执行或新的进程边界。

时间线处在事件之间时，图旁说明区分“正在进行”和“完成后”。不能一边画数据在途，一边亮起“全部可用”。展示数值形成过程时，可揭示实际计算步骤或明确标注绘制进度；不要把 0.5 条请求、尚未归一化的插值权重、部分填充的格子称为已完成数量。完成后保留本次解释所需的输入、结果和触发约束。

## 旧图取舍清单

逐图核对当前页面和实际交互，记录“读者问题 / 旧图缺口 / 独有信息 / 处理方式 / 新图验收”，不要仅按文件名或新旧发布时间决定删除。

| 处理方式 | 判定条件 | 如何处理 |
| --- | --- | --- |
| 替换 | 图形本身暗示了错误关系，或新图已覆盖旧图全部教学作用 | 用正确表示替换；同一问题只保留一个主入口；迁移必要文案、自测、来源和旧链接 |
| 合并 | 旧播放器仍有独有参数或数值，但主过程与新图重复 | 把独有条件纳入同一模型和控件；避免同页两套互不关联的播放状态；不能只删掉少见分支 |
| 补过程 | 空间布局、时间格或数值表本身正确，只缺中间计算或条件变化 | 在原图加贡献形成、写入、依赖或门槛变化，保留读者已能理解的结构 |
| 保留 / 深入 | 提供新主图没有的精确矩阵、源码边界、失败分支或复杂多请求实验 | 说明独立学习目的，按先修关系渐进展开；展开区不是重复播放器的收纳箱 |

优先替换：无具体载荷的循环光点、只换标题的卡片、只有始末状态的跳切、把物理地址画成队列移动的图、混淆通知与完成的单线流程。优先合并：已由主图完整解释的旧 tokenize、生成、Attention 或 KV 演示。应先检查覆盖再决定，不能因为同名就删除——例如 Attention 中后续层的数值实验、KV 的共享保护和调度的回撤，可能仍有独立价值。

并行分片、PP 时间格、候选前缀与 KV 对齐、性能计时轴不因“静态”或“旧”就失去价值。先判断它们缺的是结构，还是操作过程；不要又把这些专用图改回通用三列卡片。

## 选择场景

| 学习问题 | 画面与操作 | 必须看见的结果 | 容易误导的地方 |
| --- | --- | --- | --- |
| Prefill 和 Decode 各做什么 | 输入/输出 token 条与 KV 槽；单步生成 | 输入处理、采样输出与下一步 KV 更新的先后 | 把可见输出 token 数直接等同已写 KV 数 |
| 为什么请求排在前面却未进入 batch | 待选队列、准入门与分开的预算槽；改变一项预算 | 候选、接纳、等待的差别及触发约束 | 排序等于接纳；输入、KV、请求行容量混成一个数 |
| Chunked Prefill 怎样让长短请求共存 | token 分块条、轮次与预算消耗；改变 chunk 限额 | 已处理部分、剩余部分和下一轮依赖 | 虚构某个 chunk 值总能提高吞吐 |
| 共享前缀为什么省 KV | prefix tree、逻辑到物理块映射与引用保护；切换前缀/回收 | 复用边界、共享块和可释放块不同 | token 相同就必然可复用；请求结束立即释放所有共享块 |
| TP、PP、DP 如何分工 | 张量分片、stage 泳道或副本队列，按机制独立呈现 | collective、前后级依赖或单个请求归属 | 把三种并行都画成相同服务器箭头图 |
| PD 分离何时真正交接完 | P/D 双泳道，分开元数据、KV 载荷与 ready/release 条件 | 两侧状态和资源归属，失败分支的等待/回收 | 发出元数据即完成传输；一端完成代表另一端全部就绪 |
| 取消为什么不是立即清空 | 请求状态与在途 GPU/通信分轨；在关键步骤取消 | 取消标记、通知和安全释放的顺序 | HTTP 返回等于 GPU 停止；错误路径立即重用在途缓冲区 |
| TTFT、ITL、TPOT 怎么读 | 带起止点的请求时间轴与数据包；切换采样边界 | 相同样本在不同边界下的计时含义 | 教学步长冒充毫秒；包间隔冒充逐 token 间隔 |

## 一个可实现的调度课设计

目标：读者能区分“排队优先级”和“当前能否接纳”。先核对本课固定基线中的准入逻辑，再决定示例参数与拒绝理由。

1. 用 A/B/C 三条请求，显示已知输入、待执行阶段与本轮预算，术语放在对应对象旁。
2. 让读者预测首个候选是否会被接纳。给图上的候选路径、准入门和预算占用各自明确的语义。
3. 点击“下一步”：候选移动到准入门；根据教学模型进入 batch 或留在等待位置，展示具体限制。
4. 改变一项预算后重算同一组输入。用前后图形对照解释原因，不凭空声称延迟或吞吐改善。
5. 重置恢复初始状态。展开区提供当前限制的固定源码入口，以及简化模型没有表达的其他路径。

验收重点：队列与 batch 请求守恒，资源占用符合模型约束；拒绝与接纳均能在图中辨认；切换参数不遗留旧对象；键盘可以完成同一实验；减少动态效果时仍可看出相同结果。

## 动画和交互的实现约束

维护可复现的逻辑步骤列表或状态转移函数；有随机输入时固定种子并允许重置。渲染读取当前快照，动画计时不反向决定调度结果。暂停应冻结当前演示，重置要取消未完成计时器；离开页面或切换场景后不保留后台播放。

将逻辑事件与视觉过渡分开：先根据参数确定合法事件及前后状态，再用过渡进度生成画面。为请求、token、缓存块设置稳定标识，保持其位置或尺寸变化可追踪，避免每一步清空整个场景后突然出现新卡片。跨区域移动表示调度归属或数据传输时，要就近说明语义；从等待区移入执行区不自动意味着发生跨设备内存复制。

时间线暂停应冻结对象位置、增长进度及与其对应的说明，而不只是停止步骤计数。恢复从同一进度继续；回看或拖动进度不得重复触发逻辑入队、释放、计数等副作用。GSAP 负责呈现，调度和资源状态仍由教学模型决定。

回退可采用已保存的不可变快照或从初始状态重放，不为简单教学状态引入不可维护的双向更新。改变参数后按页面约定暂停并重建步骤，保持图形、说明、可用按钮和自测答案一致。

为状态加标签，并保留清楚的图例。触控用户应有点击/按钮替代 hover 与拖拽；键盘焦点可见；状态变化不要通过高频屏幕阅读器播报制造噪声。

## 动画过渡验收

对本次受影响的关键过渡，在真实浏览器中检查：

1. **身份连续**：选中一条请求或一个数据块，沿起点、中途、终点持续识别它。来源颜色不随设备或状态改变，片段与副本可追踪；新计算结果能追溯输入贡献。排序变化不改变身份，复制和引用不会造成请求或资源重复计数。
2. **过程可见**：实际观察位移、尺寸、数量或连接如何演变。保留多个时刻的截图或短录屏；自动检查可采样同一对象的几何属性及模型状态，不能仅检查标题、计数或动画 API 是否存在。
3. **中途可读**：在移动或增长尚未结束时暂停，等待后确认图形与说明都不再前进；读者能辨认当前对象、来源、目标及触发条件。恢复不会跳到下一张卡片。
4. **控制一致**：单步展示同一事件的过渡，回看能恢复对应状态；中途重置、改参数、折叠实验或离开页面后，旧时间线不会继续修改新场景。减少动态效果模式保留相同因果信息与最终状态。
5. **语义同步**：中途不提前显示已写入、已提交或已就绪；离散数量与教学进度不混用。最终结果保留触发原因，例如 `需求 < 可用量` 不成立，不能只剩空列表。
6. **空间可读**：实际查看浅色和深色的关键帧及中间态；箭头不穿过无关对象或盖住文字，文本与背景对比清楚，窄屏不靠缩成难读小字来“通过不溢出检查”。桌面与手机的图形可以重排，但不能改因果关系。
7. **核心一目了然**：从该概念入口开始，不读长文也能指出输入、关键动作和结果，并解释它与相邻概念的区别。核心关系完整且突出，次要细节不抢占注意；没有夹入参考复合图中的其他计算。跨 rank 的结果数量、归属和形状正确，拼接、复制与归约的动作可区别。
8. **并发正确**：在共享阶段的中点观察，没有依赖的动作同时推进；有依赖的消费未提前开始。路径布局没有把独立动作改成串行，也没有凭空增加中间阶段。
9. **节奏有效**：以默认速度完整播放，关键转换有足够时间看懂，重复动作不拖沓。播放中调整速度滑块、暂停并恢复，位置连续，语义顺序与结果不变；不靠读者先减速弥补默认节奏缺陷。

连续批处理的验收样例：请求 A/B/C 从等待区进入批次，各自新增 token；A 完成后退出，空位出现，新请求 D 才按准入条件补入，B/C 的身份和生成进度持续保留。不能用整张 batch 卡片替换或无语义的闪烁代替这些过程。实际事件先后以该课程固定源码与简化范围为准；动画时长只控制阅读节奏，不表示真实 GPU 耗时。

用户提供的视觉参考：[SgLang代码细读-1.从req到batch](https://www.cnblogs.com/sunstrikes/p/18884152) 中的“3.ScheduleBatch构建”动图。可参考固定空间分区、同色请求连续移动和 token 增长的表达；它不是本仓当前源码版本的实现证据，也不要求复用原图资产。

## Skill 场景复核

使用本 Skill 时，用当前任务检查它是否产生正确取舍：

- “重做整个 Pages”：先盘点课程和共享层，完成跨课一致性与导航验证，不能只交一张首页。
- “把调度动画做得更好懂”：先确认准入约束，再改变队列、预算和请求运动；不能仅加装饰动画。
- “做成鲁大猿的风格”：先查实际参考，借鉴问题驱动与条件变化；无法看到作品时明确证据缺口，不能臆造颜色和构图。
- “展示真实 SGLang 性能收益”：要求来自对应版本、硬件、负载与计时边界的数据；教学模型不能产生真实 benchmark 结论。
- “新版很好，哪些旧图可以替换”：按旧图独有的知识与交互判定替换、合并、补过程或保留；不能只列所有旧文件，也不能把它们一律折叠后称作完成整理。
- “所有页面加统一动画”：统一身份、颜色和控件规则，按机制分别选择查表、地址格、序列和时间轴；不把视觉一致误解为图形同构。
- “只调整按钮文案”：保持小范围修改和相称验证，不把整个网站迁移到新框架。
