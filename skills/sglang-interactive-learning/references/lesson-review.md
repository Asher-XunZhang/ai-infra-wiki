# 按机制复核一章课程

整站检查或从成功案例推广规则时读取。规则约束理解效果，不要求所有课程长成同一张图。

## 从并行课抽取的改法与验收

| 改法 | 可迁移规则 | 验收问题 |
| --- | --- | --- |
| 先展示 X、W、形状与行列含义 | 先给完整输入和读图单位，再做切分 | 初学者知道被切的是什么吗？ |
| 用一个输出格解释点积 | 第一次关键转换要有可手算的最小例子 | 结果是否能从输入算出，而非突然出现？ |
| 标出切分轴，追踪同色分块 | 图形编码服务于维度、身份或归属 | 颜色、编号和移动途中含义是否一致？ |
| 分别展示局部乘积、求和与拼接 | 显示局部工作，再解释结果如何使用或汇总 | 相加、拼接、路由、释放是否被混画为同一种动作？ |
| 两种 TP 分法还原同一结果 | 用共同输入比较单个机制差异 | 读者比较的是策略，还是两套无关输入？ |
| PP 从层链进入时间格；DP 使用完整副本 | 为子机制分别选图，不把所有内容塞入共用模板 | 图形本身能解释该机制的结构与依赖吗？ |
| EP 路由表连接 token、专家和返回位置 | 对选择性分支显示选择依据与归位规则 | 为什么选这个对象，结果回到哪里？ |
| SP 展示完整行与布局转换，PCP 展示因果矩阵 | 保留维度、读取范围和远端依赖 | 是否把布局变换误画成计算完成？ |
| DCP 从 Q/K/V 算到局部 O/Z，再加权 | 归一化、预算等关键数值须显出来源 | 读者能解释为何不能简单平均吗？ |
| 保留输入、局部贡献，移动副本 | 原件、引用、副本和所有权分别画 | 最后一帧是否还留着结果的原因？ |
| 先选并行策略，再选该策略的场景 | 机制导航和条件参数分开 | 场景选项是否只属于当前机制，切换是否重置并恢复链接？ |
| 对照表、策略导航、收益/代价、展开推导 | 先建立阅读地图，再渐进展开 | 不读长文能否定位问题，且看到关键限制？ |
| 术语、载荷与设备边界就近标注 | 短图例不能全部藏到术语表或源码区 | 读者能独立解释每个缩写及箭头吗？ |
| 保留正文、自测、原参数分支与固定源码 | 整合重复入口，不丢独立教学用途 | 旧图移除后，其独有条件是否仍可操作或有明确入口？ |
| 检查中途、回看、窄屏和无 JS | 测试行为不变量，截图检查读图效果 | 是否只有终态正确，过程却误导或文字过小？ |
| 仅本地构建，区分教学和实测 | 交付满足用户发布边界，不借动画证明真实性能 | 是否清楚哪些是示例，哪些来自固定源码？ |

## 逐章执行

1. 枚举实际课程入口、该课承诺的子机制、现有主图、保留实验与正文。先读已有导航与交互代码，不把“找不到入口”立即判为“没有机制”。
2. 为每个子机制作出一个判断：保留、补中间过程、重画、合并重复入口、调整阅读层级。写明证据与原因；“保留”也需要说明独立用途。按 [成熟教学图的拆解方法](mechanism-patterns.md#从成熟教学图提炼独立动画) 查阅并观察相关教程，记录来源、借鉴点和不适合本课的部分；复合图分成单概念入口，不只查整章标题后套用同一张图。
3. 先写出每个概念必须让初学者一眼明白的核心行为，检查关键关系是否完整、视觉重点是否明确；背景、重复过程和实现细节按需要弱化。优先修复错误因果、对象混淆与知识跳步，再整理导航和文案。按 [从结果反推必需的解释](mechanism-patterns.md#从结果反推必需的解释) 检查数值来源、状态触发条件、等待原因和比较边界；只补当前概念所需的因果环节。共享控件只能统一操作，不统一机制画法。
4. 合并旧图前列出独有输入、条件、失败分支、自测、源码和锚点。对照新入口逐项确认可达；不能只凭标题相似删除。
5. 按实际修改选择检查。数学关系用独立算例核对，资源图检查守恒和释放条件，动画检查来源颜色、持久对象、中间态、独立动作并发及默认节奏，导航检查合法组合和链接恢复。逐章记录结论与未覆盖范围，不以“全站通过”掩盖只检查若干页面。

## 阅读层级的取舍

- 三个短段落能直接解释一个问题时，保留正文；不要为了统一外观增加多层折叠。
- 同一机制有多种条件时，用场景选择器；不同机制并列时，先提供机制入口。
- 收益与代价适合相同维度的对照；状态机适合按阶段导航；源码导读适合“行为 → 对象 → 固定锚点”。
- 长生命周期已有分阶段侧栏时，优先分开概览、推进条件和实现细节，不再叠加重复导航。
- 折叠只减少初始信息量，不删除内容；关键适用条件保持可见，锚点访问时展开包含目标的层级。

## 本轮推广中补充的规则

- 已有正确的矩阵、时间轴、池映射或状态机可以保留；审查记录写出它让读者回答的独立问题，不为了“全覆盖”重复重画。
- 分层控件保持独立变量：切换排序策略时保留资源条件，避免把同时改变两个条件的结果归因于单一策略。原场景 URL 索引保持稳定。
- 请求数、token 数、页数等是离散账目。过渡可显示 `旧值 → 新值（变更中）`，填充条表示动作进度；不得把插值小数标成当前已提交数量。
- 静态全文、条件选项与动态算例要核对同一输入规模；不同实验使用不同假设时，分别明确人数、位置数、时间单位和调度策略。
- 迁移旧图时，连同独有条件和测试断言迁移，不留下重复教学入口；相邻专题的重复图可换为指向权威课程的链接。
- 对象路径尽量避开其他输入和解释文字，通过布局、间距、弧线或视觉层次保持可读。只有机制本身存在依赖或资源限制时才分批、排队；不得用串行播放解决并发动作的遮挡。截图检查中途身份与数据去向，而不仅检查画布溢出。

## 基础章的概念边界

基础章先帮助读者认识概念本身。主图中的每个对象、区域和步骤都应能解释为该概念必需的参与者、输入、操作、结果或约束；实现章再展开引擎对象、算法、通信后端和部署配置。

- 优先直接呈现行为：Broadcast 展示同一份数据复制给各方，Scatter 展示不同片段分给对应参与者，AllToAll 展示按目标交换并得到相应结果。源与目标已经清楚时，不另加“独立交接”视图、运输队列或路由矩阵作为必经步骤。
- 必需的中间过程仍保留：归约必须能看到数值如何合并，Barrier 必须显示先到者等待，匹配接收和消费者依赖不能省略。简洁不等于仅给终态、隐藏约束或跳过关键计算。
- 特定算法及实现细节通过就近链接或进阶说明承接；只有该课明确以该算法为主题时，才把其内部阶段放入主图。例如通信语义不预设 ring、tree 或中央归约节点。
- 参与方、载荷、设备／主机边界只用当前理解所需的短标签交代。已有标注足够时，不重复增加拓扑面板；不让读者先学会一套辅助视图才能认识基本行为。
- 验收逐项问：删掉这一层是否仍能准确解释概念？保留它会不会让初学者以为所有实现都必须经过这里？若没有独立教学价值就移除；并发动作与真实依赖不因简化而改变。

## 概念深度与实现动机

逐章先检查读者能否回答：为什么要引入这个概念？没有它时会遇到什么问题？它具体改变了哪一步？收益和代价分别是什么？术语释义、函数名和动画终态齐全，不代表这些问题已经解释清楚。

- 从具体矛盾切入，例如多条请求长度不同但要组织一次 forward，或传输尚在使用源 KV 但请求已经生成完成。再解释解决它的对象、字段和条件，避免先抛函数清单让读者自己猜目的。
- 用一个可核对的输入或反例连接问题与机制。基础章讲一般原理；实现章说明该版本如何组织这些原理，链接已有基础说明，不重复整套数学入门。
- 取舍紧邻机制：节省什么，额外保存、计算、通信或等待什么；哪些条件会限制收益。源码未说明设计者动机时，把解释标为基于行为与约束的理解，不冒充作者声明。
- 概念补充先查官方文档、项目作者文章或原论文，再用固定源码确认本课行为；不能只读代码便宣称解释了设计动机。引用就近注明支持的内容、时间和版本；当新版文档的参数或协议不同，明确区分。教程可帮助选择表达，事实以原始资料复核；背景按学习价值选用。不要把所有概念强行排成一条历史演进链，也不要为了显得深入加入无关年代。
- 核心问题和简短因果解释直接可见，详细推导、历史背景和代码按需展开。原有充分内容通过直接锚点引导；不得以补充为由复制同一课已有段落。
- 验收增加一个因果问题，例如“删掉这层映射会失去什么”“通知先到为什么还不能读”“容量增加后哪个约束仍然存在”。逐章记录缺口、补充与保留理由，并保持固定源码和教学例子的边界。
